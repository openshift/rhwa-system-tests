## 2. Summary

With `StorageBasedRemediationConfig.spec.detectOnlyMode: Enabled`, the SBR agent never arms
a watchdog — it substitutes a no-op mock — so it must start and stay Ready on nodes where
`/dev/watchdog` is held by another process (typically SNR) or is missing entirely. The
watchdog portion of `runPreflightChecks()` must be skipped; the SBR device check and node ID
resolution must still run.

## 3. Scope

- **In scope**:
  - Every agent pod of a `detectOnlyMode: Enabled` SBRC reaches Ready while a privileged
    keepalive pod holds `/dev/watchdog` open on each worker node, and no pod — current or
    previous container — logs `Pre-flight checks failed: watchdog device is not available`.
  - The same with `spec.watchdogFilePath` pointing at a device that does not exist, which
    proves detect-only mode needs no watchdog at all rather than merely tolerating a busy one.
  - The skip is scoped to the watchdog: an otherwise-unsatisfiable preflight (unresolvable
    shared storage device) still prevents the agent from going Ready in detect-only mode.
- **Out of scope**:
  - Everything OCP-88876 already proves about the field itself — spec reflection,
    storage-fault suppression, the Enabled/Disabled toggle, and DaemonSet garbage collection.
    This test case does not restate those assertions; see section 12 for why it stays a
    sibling spec rather than being folded into OCP-88876.
  - Watchdog behaviour when `detectOnlyMode` is `Disabled`, where arming a real watchdog is
    required and a busy device is a legitimate startup failure.
  - Whether a hardware watchdog or softdog is present on each node at all, which is
    OCP-88878 (`watchdog.go`).
  - Any fencing or remediation outcome. Detect-only mode suppresses fencing by definition,
    and the suppression itself is OCP-88876's assertion.

### Relationship to what already exists

`detect_only.go:412` already contains a spec for this behaviour:

```go

```

It is close to what RHWA-1187 asks for, but it is not usable as coverage today:

| Problem | Consequence |
| ------- | ----------- |
| Gated behind `SBR_TEST_RHWA1068=true`, with the comment "bug not yet fixed in the current operator version". | It `Skip`s on every default run, so nothing is verified. RHWA-1184 is ON_QA, so the gate's premise no longer holds for 5.0. |
| The keepalive pods in `BeforeAll` are created under the same env var. | Even when the spec runs, the precondition is absent unless the variable is set — the assertion would pass vacuously on a node with a free watchdog. |
| No `reportxml.ID`. | Violates `docs/TESTCASES/AGENTS.md`; the result appears in no report and cannot be tracked against a ticket. |
| Attributed to RHWA-1068, which is Closed. | The 5.0 recurrence (RHWA-1184) has no traceable coverage. |
| Only the busy-device case; the missing-device case is untested. | "detectOnly works **without the need for** a watchdog device", the actual ask on RHWA-1187, is only half covered. |
| Does not assert that the non-watchdog preflight checks still run. | A regression that skipped *all* of preflight in detect-only mode would pass. |

So RHWA-1187 is satisfied by reworking that spec rather than adding a new one: remove the
gate, create the keepalive pods unconditionally, assign `reportxml.ID("1187")`, and add the

## 5. Preconditions

Asserted in `BeforeAll`:

1. The SBR operator deployment is Ready.
2. An RWX StorageClass is discoverable, or `SBR_STORAGE_CLASS` names one; otherwise skip.
3. At least one schedulable worker node exists, and at least one hosts no SBR controller pod.
4. Self Node Remediation is **not** required to be running. SNR is the usual real-world
   holder of `/dev/watchdog`, but this test creates its own keepalive pods so it does not
   depend on SNR being installed, and must not skip when it is absent.
5. Any `test-sbrc-detect-only` SBRC left by an earlier run is deleted and fully gone before a
   fresh one is created.
6. A privileged keepalive pod is Running on every schedulable worker node and holds
   `/dev/watchdog` open — created unconditionally, not behind an env var. A node where the
   pod cannot start is logged and excluded; if **no** keepalive pod starts anywhere, the
   spec fails rather than passing vacuously.
7. The `detectOnlyMode: Enabled` SBRC is created only *after* the keepalive pods are
   Running, so the agents meet a busy watchdog on their first start rather than after a
   restart.

## 6. Test steps

| #  | Step (`By` text)                                                                                      | Expected result                                                                               |
| -- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1  | Verifying a watchdog-keepalive pod holds /dev/watchdog on every worker node                               | At least one keepalive pod is Running and has the device open                                     |
| 2  | Asserting ALL agent DaemonSet pods are Ready — none should be in CrashLoopBackOff                         | `NumberReady == DesiredNumberScheduled` for `sbr-agent-test-sbrc-detect-only` within `sbrparams.DetectOnlyAllPodsReadyTimeout` |
| 3  | Verifying no agent pod log contains the watchdog preflight crash message                                  | `Pre-flight checks failed: watchdog device is not available` is absent from every agent pod's current log, and from the previous container of any pod that restarted |
| 4  | Verifying no agent pod has restarted while the watchdog was held                                          | Every agent pod's `restartCount` is 0, so the agents started cleanly rather than recovering from a crash loop |
| 5  | Patching the SBRC watchdogFilePath to a device that does not exist                                        | The SBRC accepts `/dev/sbr-nonexistent-watchdog` and the agent DaemonSet rolls out              |
| 6  | Asserting ALL agent pods are Ready again with no watchdog device present at all                           | `NumberReady == DesiredNumberScheduled` within `sbrparams.DetectOnlyAllPodsReadyTimeout`, proving detect-only mode needs no watchdog rather than merely tolerating a busy one |
| 7  | Verifying the agents still report the shared storage device as healthy                                    | Each agent logs a successful SBR device open and node ID resolution, so only the watchdog portion of preflight was skipped |
| 8  | Restoring the original watchdogFilePath and waiting for the DaemonSet to roll out                         | The SBRC returns to its original spec and all agent pods are Ready                              |
| 9  | Deleting the watchdog-keepalive pods to release /dev/watchdog                                             | Every keepalive pod is gone and the device is released with the magic-close character           |

Step 7 is the scope check for the fix. RHWA-1184's accepted fix is "skip the watchdog portion
of `runPreflightChecks` when detectOnlyMode is true. The SBR device check and node ID
resolution checks should still run." Without step 7 a regression that skipped preflight
entirely would pass steps 2 through 6.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1187")` runs and passes, with no `Skip`.
- With `/dev/watchdog` held open on every worker node, all pods of the
  `sbr-agent-test-sbrc-detect-only` DaemonSet reach Ready within
  `sbrparams.DetectOnlyAllPodsReadyTimeout`, and every pod's `restartCount` is 0.
- No agent pod logs `Pre-flight checks failed: watchdog device is not available`, in either
  its current or its previous container.
- With `spec.watchdogFilePath` pointing at a non-existent device, all agent pods reach Ready
  again within the same timeout.
- Agent logs still show the SBR shared-device open and node ID resolution succeeding, so the
  preflight skip is scoped to the watchdog.
- Cleanup finishes: the keepalive pods are gone, `/dev/watchdog` is released, the SBRC's
  `watchdogFilePath` is back to its original value, and the detect-only SBRC and its agent
  DaemonSet are removed.

On a build without the RHWA-1184 fix this spec fails at step 2: every agent exits with the
preflight error and `NumberReady` stays at 0 until the timeout. That is the regression it
exists to catch.

## 9. Cleanup

- `DeferCleanup` restores `spec.watchdogFilePath` to the value captured before step 5 and
  waits for the agent DaemonSet to roll out, so a failure between steps 5 and 8 does not
  leave a broken SBRC for later specs.
- `DeferCleanup` deletes the watchdog-keepalive pods. The keepalive command writes the
  magic-close character `V` to the device before closing it, so releasing the watchdog never
  resets the node; `deleteKeepalivePods` tolerates a pod that is already gone and logs with
  `GinkgoT().Logf` instead of failing.
- `AfterAll` removes the `test-sbrc-detect-only` SBRC and waits for it to be fully gone,
  tolerating `IsNotFound`, and removes any remaining keepalive pods as a second net.
- Keepalive pod creation is best-effort per node: a node where the pod cannot start is logged
  and skipped, but the spec fails if no keepalive pod started anywhere, so a vacuous pass is
  not possible.

## 12. Implementation sketch

Reworks the existing spec at `tests/sbr-operator/tests/detect_only.go:412` rather than adding
a new file.

```go
It("Verify detectOnlyMode agents start and stay Ready with no usable watchdog device",
    reportxml.ID("1187"),
    Label(
        labels.OperatorSBR,
        labels.TierAcceptance,
        labels.ComponentDaemonSet,
        labels.DisruptionNonDestructive,
        labels.PlatformAny,
        labels.FrequencyNightly,
    ), func() {
        // No env-var gate and no Skip: RHWA-1184 is fixed in 5.0.
        Expect(keepalivePods).ToNot(BeEmpty(),
            "At least one keepalive pod must hold /dev/watchdog, or this spec passes vacuously")

        DeferCleanup(func() {
            By("DeferCleanup: restoring the original watchdogFilePath")
            // ...
            By("DeferCleanup: deleting watchdog-keepalive pods to release /dev/watchdog")
            deleteKeepalivePods(keepalivePods)
        })

        By("Asserting ALL agent DaemonSet pods are Ready — none should be in CrashLoopBackOff")
        // existing Eventually on NumberReady == DesiredNumberScheduled

        By("Verifying no agent pod log contains the watchdog preflight crash message")
        // existing current-and-previous-container log scan

        By("Verifying no agent pod has restarted while the watchdog was held")
        // new: restartCount == 0

        By("Patching the SBRC watchdogFilePath to a device that does not exist")
        // new

        By("Asserting ALL agent pods are Ready again with no watchdog device present at all")
        // new

        By("Verifying the agents still report the shared storage device as healthy")
        // new: proves the preflight skip is scoped to the watchdog
    })
```

Changes needed outside the spec body:

- `BeforeAll` — create the keepalive pods unconditionally; drop the
  `os.Getenv("SBR_TEST_RHWA1068")` branch and the "skipping watchdog-keepalive pods" log.
- `sbrparams` — add the non-existent watchdog path used in step 5 and the log substrings
  asserted in step 7 as named constants, alongside the existing
  `DetectOnlyAllPodsReadyTimeout` and `WatchdogKeepaliveTimeout`.

### Why this stays a sibling spec rather than being folded into OCP-88876

RHWA-1187 is worded as enhancing "the OCP-88876 test", and both specs live in the same
`Ordered` container, so the keepalive precondition in `BeforeAll` is shared either way. They
are kept as two `It`s because:

- OCP-88876's subject is the `detectOnlyMode` field — reflection, fault suppression, toggle,
  GC. This test's subject is agent startup with no usable watchdog. One failure each is
  diagnostic; a single merged spec covering both would report one failure for two unrelated
  regressions.
- OCP-88876 injects a CephFS fault with a privileged injector pod and toggles the mode, which
  restarts every agent. Adding a `watchdogFilePath` patch and a second full DaemonSet rollout
  into the same `It` roughly doubles its runtime for no added coverage.
- OCP-88876 has an existing Polarion ID and history. Changing what it asserts breaks
  comparability with previous runs; a sibling spec with its own ID does not.

If a reviewer prefers one spec, the merge is mechanical — the assertions above append to
OCP-88876's body — but then RHWA-1187 gets no `reportxml.ID` of its own and the sub-task has
no traceable result.
