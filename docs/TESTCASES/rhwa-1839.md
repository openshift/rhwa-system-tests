## 2. Summary

These tests check BlockPerNode behavior through host boot IDs and public Kubernetes resources.
They check requested remediation, autonomous remediation, storage reporting, normal deletion, and host recovery.

## 3. Scope

- In scope: all 28 active cases in the current `sbr_block_tests.md` plan.
- Out of scope: matrix rows 13 and 14, version upgrades, rollout tests, power loss, and general kernel-freeze qualification.
- Out of scope: lost, corrupt, and unknown journal history. The tests never read or compare journal contents.
- Out of scope: reboot mechanism attribution, application writes, VM startup, and volume-detach evidence.
- Optional assertions appear in Section 7. They do not affect the initial result.

All 28 cases explicitly configure a one-minute autonomous recovery period. The tests no longer cover an explicit five-minute value.
The tests do not cover defaulting when the field is omitted.
A changed boot ID does not count unseen boots before SSH returns. It also does not identify the reboot mechanism.

### Fault definitions

All faults use test-owned rules or handles. Preserve management traffic and unrelated host rules.
Discover all relevant IPv4 and IPv6 endpoints before activation.
Do not assume that the fixed Ceph port range in an older test covers every deployed endpoint.

| Fault | Required effect and confirmation |
|---|---|
| API loss | Reject access to all API addresses used by the target host, agent, and reporter. Confirm failed transport from the affected network namespace. Keep the runner's API connection available. |
| Storage loss | Reject traffic to the selected RBD backend's advertised monitor and OSD endpoints. Confirm installed rules and matching traffic. The API remains reachable unless explicitly blocked. |
| Storage timeout | Drop the same storage traffic. Confirm installed rules and matching traffic. Do not assert a particular kernel I/O state. |
| Storage latency | Add exactly LATENCY to selected storage traffic with `tc`. Keep API and SSH traffic outside that class. Confirm the selected traffic uses that class. |
| Single-node isolation | Block the target's cluster traffic and API traffic. Preserve storage traffic and the actual SSH connection. |
| Group partition | Block cluster traffic between worker A and workers B/C in both directions. Preserve API, storage, and SSH traffic for all three. |
| Kubelet stop | Run `systemctl stop kubelet` through SSH. Confirm that kubelet is inactive. Leave CRI-O and the agent running. |
| Journal access | Set the existing host state directory immutable. Confirm that a test-owned temporary file cannot be created there. Do not alter journal files. |

Network faults must cover the agent's actual network namespace as well as relevant host traffic.
A rule that does not affect that traffic does not establish a fault.
Fault confirmation is a prerequisite for assessing the SBR result. It is not a check of SBR's internal behavior.

For faults that must survive reboot, install a test-owned host service before activation.
It must restore the owned network rules before kubelet and SBR can resume communication.
Check service ordering before the first outage. Check the rules again after reconnection.
A healthy interval caused by missing rules invalidates an unresolved-outage assertion.
This service contains only host commands. It uses no image or external service.

Establish the first combined outage in this order:

1. Activate persistent storage loss while the API remains reachable.
2. Require `SBRStorageUnhealthy=True` within HEALTH_CHANGE.
3. Activate persistent API loss. Start REBOOT after confirming both faults.

This sequence supplies a prior True condition for the later recovery observation.
NHC remains paused throughout this sequence.

For short recovery windows, use conservative time bounds:

- Start the possible healthy interval when the runner dispatches the first restoration command.
- End that interval when the runner confirms the next API or combined fault.
- Start confirmed healthy time only after observing False storage health and live API transport.
- End confirmed healthy time when the runner dispatches the next fault command.

Require each possible healthy interval to remain strictly shorter than 60s in cases 17C and 17E.
Command delays count toward that upper bound. A timing miss is INCONCLUSIVE.
