## 2. Summary

After deployment, every SNR DaemonSet pod container must set
`securityContext.readOnlyRootFilesystem` to `true`. This validates the fix for
DAST finding KSV014 (AVD-KSV-0014): an immutable container root filesystem stops
a compromised container from writing to its own root filesystem, though not to
separately mounted volumes.

## 3. Scope

- **In scope**: Verifying that every SNR DaemonSet agent pod's container (and
  init container) sets `securityContext.readOnlyRootFilesystem=true`.
- **Out of scope**: The DaemonSet manifest itself (covered by the upstream fix
  in medik8s/self-node-remediation#309); the SNR controller-manager pods; other
  DAST findings; pod security admission enforcement.

## 12. Implementation sketch

A dedicated `It` in `post_deployment.go`, backed by a helper in `helpers.go`:

```go
It("RHWA-1984: Verify SNR DaemonSet containers set readOnlyRootFilesystem (KSV014)",
    reportxml.ID("1984"),
    Label(labels.TierSmoke, labels.DisruptionNonDestructive,
        labels.PlatformAny, labels.FrequencyPresubmit,
        labels.ComponentDaemonSet), func() {
        By("Waiting for SNR DaemonSet pods to be running")

        Eventually(verifyDSPodsRunning,
            medik8sparams.DefaultTimeout, snrparams.DefaultPollInterval).Should(Succeed(),
            "SNR DaemonSet pods are not all running and ready")

        By("Verifying SNR DaemonSet containers set readOnlyRootFilesystem (KSV014)")

        Expect(verifyDSPodsReadOnlyRootFilesystem()).To(Succeed(),
            "SNR DaemonSet containers must set securityContext.readOnlyRootFilesystem=true "+
                "per DAST finding KSV014 (AVD-KSV-0014)")
    })
```
