# RHWA-2038 — SBR startup clears the unused preflight heartbeat on Ceph RBD block storage

## 1. Metadata

| Field                        | Value                                                   |
| ---------------------------- | ------------------------------------------------------- |

| `reportxml.ID`               | `2038`                                                  |

| Author                       | rwurmbra                                                |

This is the Block-mode version of the Filesystem ghost peer regression
([RHWA-1964](rhwa-1964.md), `ghost_peer.go`), which covers
[RHWA-1058](https://redhat.atlassian.net/browse/RHWA-1058). During preflight every
agent writes a test heartbeat as node ID 1. The operator passes no `--node-id`, so
that is the default ID. Once the node map gives the agent a different ID, the agent
must zero that slot again. If it doesn't, every peer keeps monitoring a node that
doesn't exist. In Block mode, node ID 1 is heartbeat slot index 0
(`(nodeID - 1) * 4096`), not slot 1 as on a filesystem, and the agent clears the
whole 4 KB slot (`clearPreflightSlot`, checked against upstream `main` @ `6c98b1cd`).

## 2. Summary

Verify that SBR agents on a Ceph RBD Block device zero heartbeat slot index 0,
where preflight wrote its test heartbeat as node ID 1, when no real node owns node
ID 1. The agents must stay Ready without restarts while the slot is observed.

## 3. Scope

- **In scope**: RHWA-1058 in Block mode on Ceph RBD: the preflight heartbeat in
  heartbeat slot index 0 is cleared once the agents get their hash-based node IDs.
  The full 4096-byte slot must stay zero through every agent for one minute. Also
  in scope: every agent is registered in the on-device node map with a unique ID,
  and the agents stay stable.
- **Out of scope**:
  - The same regression on RWX **Filesystem** storage, where slot 1 is at offset
    512 (`ghost_peer.go`, [RHWA-1964](rhwa-1964.md)).
  - A real node owning node ID 1. Slot index 0 then holds that node's own
    heartbeat, so the spec skips. Node IDs are hash-based, so on some clusters this
    is expected.
  - That preflight wrote the slot first. The test proves the slot ends up zero.
    That only exercises the clear because the operator passes no `--node-id`. If
    the operator ever starts passing one, this test would pass without exercising
    the clear and needs revisiting.
  - Static on-disk layout: superblock, node map, and slot-to-node-ID agreement
    (`block_storage_inspection.go`, [RHWA-1926](rhwa-1926.md)).
  - Fence slot geometry and fencing on Block (`block_storage_fence_geometry.go`,
    [RHWA-2031](rhwa-2031.md)).
  - Peer-log content and phantom-peer metrics. The bug has no effect visible on
    the API: no Node maps to node ID 1, so nothing is flagged or remediated. For
    that reason the spec doesn't record nodes or remediation CRs.

## 5. Preconditions

`BeforeAll` checks, in order:

1. The SBR controller deployment is Ready within `medik8sparams.DefaultTimeout`.
   Its container images are attached to the report.
2. No NodeHealthCheck remediates through the SBR template. Skip otherwise.
3. No SNR agent DaemonSet or agent pods remain, because SNR and SBR can't share
   the watchdog. Skip otherwise. Stop SNR before running and save its
   configuration so you can restore it afterwards.
4. Any leftover SBRC labelled `test.medik8s.io/ghost-peer=true` is deleted, and
   the spec waits for its operands to be gone. Unrelated SBRCs are never deleted.
   If any remain, the spec skips.
5. At least two workers are Ready and schedulable. Skip otherwise.
6. A Ceph RBD StorageClass is found. Skip otherwise.
7. Leftover Ceph OSD blocklist entries from earlier destructive Block specs are
   cleared before the SBRC is created. They can stop the RBD device from attaching
   or slow down heartbeats. This is best-effort and never fails the spec.

## 6. Test steps

Steps 1–6 run in `BeforeAll`, 7–10 in the `It`, 11 in `DeferCleanup`, and 12 in
`AfterAll`.

| #  | Step (`By` text) | Expected result |
| -- | ---------------- | --------------- |
| 1  | Verifying SBR is Ready | The controller is Ready and its images are recorded |
| 2  | Verifying no NodeHealthCheck remediates through the SBR template | No NHC uses the SBR template, or the spec skips |
| 3  | Verifying SNR agents are stopped | No SNR DaemonSet or agent pods, or the spec skips |
| 4  | Removing only this test's stale configurations | Leftover labelled SBRCs and their operands are gone. No unrelated SBRC exists, or the spec skips |
| 5  | Checking worker and Ceph RBD storage prerequisites | At least two Ready, schedulable workers and a Ceph RBD StorageClass, or the spec skips |
| 6  | Clearing residual Ceph OSD blocklist entries from prior tests | Blocklist cleared, or a warning is logged |
| 7  | Creating a Block-mode SBRC and waiting for its init Job and agents | A `test-sbrc-block-ghost-peer-*` SBRC with `sharedStorageVolumeMode: Block` is created. Its init Job reaches `Complete=True`, and every agent is Ready on its own node |
| 8  | Verifying node ID 1 has no real owner in the shared Block node map | Every agent's node is registered. `entries` and `node_usage` each have one row per agent, every node ID is in 1–255 and maps back to its node, and node ID 1 is unassigned. If a real node owns node ID 1, the spec skips |
| 9  | Waiting for heartbeat slot index 0 to be zero-filled through every agent | Within `medik8sparams.DefaultTimeout`, every agent reads 4096 zero bytes at heartbeat slot index 0 |
| 10 | Observing the unused slot and agent stability for one minute | For `sbrparams.GhostPeerObservationDuration`, the same pod UIDs and container statuses (including restart counts) stay in place, and slot index 0 stays fully zero through every agent |
| 11 | Removing the test configuration and waiting for its operands | The SBRC, agent DaemonSet, pods, PVC and Jobs are gone |
| 12 | Clearing residual Ceph OSD blocklist entries | Blocklist cleared, or a warning is logged |

Step 8 keeps re-reading the node map, within `medik8sparams.DefaultTimeout`, until
every agent's node is in it. An agent marks itself Ready before it joins the node
map, so a single read straight after Ready can miss one.

Step 9 waits first for the same reason. The agent creates its readiness file right
after preflight, before it gets its real node ID and clears slot index 0. On Block,
getting the node ID includes the node map's 1.5–2.5 s write-verify delay. A slot
that is never cleared fails here.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("2038")` runs and passes.
- The Block init Job completes and every agent is Ready within
  `sbrparams.SBRCReadyTimeout` (10m).
- The checksummed node map lists every agent node with a unique node ID in 1–255,
  and node ID 1 is unassigned. If a real node owns node ID 1, the spec skips
  instead of passing.
- Within `medik8sparams.DefaultTimeout` (300s), heartbeat slot index 0 (byte
  offset 135168 on the device, read with O_DIRECT) is 4096 zero bytes through
  every agent.
- For `sbrparams.GhostPeerObservationDuration` (1m), polled every
  `sbrparams.DefaultPollInterval` (5s), the agents keep the same pod UIDs and
  container statuses, and slot index 0 stays 4096 zero bytes through every agent.
  A short or failed read fails the test instead of looking like a zero slot.
- Cleanup finishes within `sbrparams.GhostPeerCleanupTimeout` (6m): the SBRC, its
  agent DaemonSet, pods, PVC and Jobs are gone.

## 8. Failure / known issues

None.

RHWA-1058 was fixed by
[product PR #69](https://github.com/medik8s/storage-based-remediation/pull/69).
On a build without the fix, slot index 0 still holds the preflight heartbeat
written as node ID 1, so step 9 times out.

## 9. Cleanup

- `DeferCleanup` deletes only the generated test SBRC, with a UID precondition. It
  waits for the operator's normal cleanup, deletes any remaining Jobs for that
  exact SBRC with background propagation, and waits for the SBRC, DaemonSet, pods,
  Jobs and PVC to be gone. Missing resources are tolerated, and operator
  finalizers are never stripped. It also runs on failure and skip, including the
  node ID 1 skip in step 8.
- `AfterAll` clears Ceph OSD blocklist entries. It's best-effort and only logs
  warnings. This spec fences nothing, so the call just keeps it consistent with
  the other Block specs.
- No recovery is needed: nothing is cordoned, tainted, rebooted or injected.
- The spec doesn't change SNR. If SNR was stopped for the run, restore its saved
  configuration after the SBR cleanup.

## 11. Running it standalone

```bash
ginkgo -v --label-filter="operator:sbr && tier:acceptance" \
    --focus="clears the unassigned preflight slot on a Block device" ./tests/sbr-operator/...
```

To follow the run, reuse the existing watch script:

```bash
watch -n 5 -d tools/watch/snr-watch.sh   # Linux, or macOS with `brew install watch`
tools/watch/snr-watch.sh --loop          # anywhere, no `watch` needed
```

The `agent pods` block lists everything in the operator namespace, including the
`test-sbrc-block-ghost-peer-*` init Job pod and agent pods. Ignore the `remediation
CRs` and `snrc` blocks for this spec. What must change: the init Job pod runs to
`Completed`, then one agent pod per worker appears and becomes Ready. What must
not change: once the agents are Ready, their names and restart counts stay the
same. All nodes stay `Ready`, uncordoned, and keep their boot IDs. No
remediation CR appears.

The script doesn't read the device. To check slot index 0 yourself, run this
read-only command against any agent pod. It prints `0` when the slot is zero-filled:

```bash
oc -n openshift-workload-availability exec <agent-pod> -c sbr-agent -- \
    dd if=/sbr-block bs=4096 skip=33 count=1 iflag=direct status=none | tr -d '\000' | wc -c
```

## 12. Implementation sketch

Implemented in
[`tests/sbr-operator/tests/block_storage_preflight_slot.go`](../../tests/sbr-operator/tests/block_storage_preflight_slot.go)
(`It("Verify SBR startup clears the unassigned preflight slot on a Block device", reportxml.ID("2038"), …)`).

It is one ordered, serial spec. It reuses the private helpers in `ghost_peer.go`
(the SNR and stale-SBRC preconditions, agent listing, SBRC client and cleanup) and
the shared Block helpers (Ceph RBD discovery, Block SBRC builder, init Job wait,
node map reader, heartbeat slot reader, blocklist clear). It adds no new helper
functions. The node map checks and the stability check are written inline in the
spec.
