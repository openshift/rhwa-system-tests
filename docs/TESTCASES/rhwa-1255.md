## 2. Summary

While a worker is under NMO maintenance, NMO holds the node's lease in
`medik8s-leases`, and NHC must not remediate that node. When the
NodeMaintenance CR is deleted, NHC acquires the lease and starts remediating
the still-unhealthy node; when kubelet is restarted and the node returns
Ready, remediation ends and the node's lease is released.

The negative half (NHC stays idle while the lease is held) is paired with a
positive control in the same run: after the hand-over, the same node — kubelet
still down — is remediated. This proves the negative window was not vacuous.
Maintenance blocks remediation both through the lease and through the
`remediation.medik8s.io/exclude-from-remediation` label NMO sets on the node;
both are removed at hand-over, so the window shows NMO maintenance as a whole
blocking remediation, with the lease as the mechanism under test.

## 3. Scope

- **In scope**:
  - During maintenance, the node lease in `medik8s-leases` stays held by NMO
    (`node-maintenance`) and NHC stays `Enabled` for the whole remediation
    window.
  - No TestRemediation CR is created while the lease is held.
  - After the NodeMaintenance CR is deleted, NHC transitions to `Remediating`
    within the same window, creates the node's TestRemediation CR, and becomes
    the lease holder.
  - After kubelet restart, NHC returns to `Enabled` and the node's lease is
    released.
- **Out of scope**:
  - The NHC lease *acquisition* algorithm (retry schedule, backoff) — only the
    observable hand-over within the window is asserted.
  - Remediation by remediators other than the TestRemediation fixture.
  - Control-plane nodes under maintenance (covered by the etcd-quorum test).
  - What NHC does with nodes it does not select.


No new variable is introduced. The spec needs SSH to the cluster nodes for
kubelet stop/start (`CLUSTER_PROFILE_DIR/ssh-privatekey`, or
`~/.ssh/id_rsa` as resolved by `helpers.FindSSHKey`) and skips with an
actionable message when no key is available: `oc debug` cannot schedule on a
node whose kubelet is down, so SSH is the only way back. On AWS this means the
ssh-bastion must be deployed (Prow does this; local runs use
`make setup-local-bastion`).

## 5. Preconditions

Asserted in `BeforeAll`, all before any cluster state is mutated:

1. An SSH key is available for kubelet stop/start.
2. The NMO operator deployment is Ready.
3. The NHC CRD is installed (skip when absent — the spec requires both
   operators) and the NHC deployment is Ready.
4. At least `NHCLeaseMinWorkers` (2) eligible schedulable workers exist,
   excluding the node hosting the NMO controller pod and the nodes hosting the
   SSH bastion.

Then, in order:

5. Pre-existing NodeHealthCheck CRs are snapshotted, then deleted (a live NHC
   selecting workers would compete for the lease once NMO releases it). The
   snapshot is restored in teardown.
6. The TestRemediation dummy-remediator fixture (two CRDs, template CR, RBAC)
   is created; only objects this run creates are torn down later.
7. Leftover TestRemediation CRs from a previous interrupted run are removed.
8. Stale NodeMaintenance CRs targeting the selected node are removed.

## 6. Test steps

| # | Step (`By` text) | Expected result |
| - | ---------------- | --------------- |
| 1 | Creating NodeMaintenance CR %s for node %s | CR is created and accepted |
| 2 | Waiting for the node to fully enter maintenance | `MaintenanceSucceeded`, node cordoned and tainted, drain completed |
| 3 | Verifying NMO holds the node lease | The node's lease exists in `medik8s-leases` held by `node-maintenance` |
| 4 | Creating NodeHealthCheck CR %s pointing at the TestRemediation template | CR is created; worker selector, minHealthy 30%, 30s unhealthy conditions |
| 5 | Waiting for NHC to become Enabled before the disruption | NHC phase is `Enabled` |
| 6 | Stopping kubelet on node %s via SSH | kubelet stops |
| 7 | Waiting for the node Ready condition to leave True | Ready condition leaves `True` within `NodeNotReadyTimeout` |
| 8 | Verifying NHC stays Enabled and does not take the lease for %s while NMO holds it | For the whole `NHCLeaseRemediationWindow`: NHC phase stays `Enabled`, lease holder stays `node-maintenance`, no TestRemediation CR exists |
| 9 | Deleting NodeMaintenance CR %s and waiting for removal | CR is gone within `MaintenanceTimeout` |
| 10 | Verifying NHC started remediating the node | NHC phase reaches `Remediating` within the same window (positive control) |
| 11 | Verifying a TestRemediation CR was created for the node | The node's TestRemediation CR (named after the node) exists |
| 12 | Verifying NHC holds the node lease | Lease holder matches the NHC identity |
| 13 | Starting kubelet on node %s via SSH | kubelet starts |
| 14 | Waiting for the node to become Ready again | Node Ready within `RebootTimeout` |
| 15 | Verifying NHC finished remediating and is Enabled again | NHC phase returns to `Enabled` |
| 16 | Verifying the node lease was released | The node's lease is gone |

Cleanup steps (DeferCleanup, best-effort): delete the test's NHC CR and
NodeMaintenance CR, restart kubelet whenever the spec attempted to stop it
(regardless of the node's current Ready condition), wait for node recovery on
the reboot-scale budget, tear down the fixture objects this run created, and
restore the snapshotted pre-existing NHC CRs.

Two steps are shaped deliberately and a reviewer should not "simplify" them:

**Step 8 reports invariant violations and API errors differently.** A broken
invariant (phase change, holder change, TestRemediation CR appearing, or the
NHC CR or lease disappearing) returns `false` and fails the window
immediately; a transient API error is retried via `TryAgainAfter` so a dropped
request is not misread as a violation.

**Cleanup restarts kubelet whenever the spec attempted to stop it**, not only
when the node currently looks NotReady: a failure between the stop and the
node leaving `node-monitor-grace-period` (~40s), or an SSH error while kubelet
actually stopped, would otherwise leave the node NotReady for the rest of the
suite. Starting an already-running kubelet is a no-op, so the unconditional
restart costs nothing.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("65651")` runs and passes.
- While NMO holds the lease: NHC stays `Enabled`, holder stays
  `node-maintenance`, no TestRemediation CR exists, for the full window.
- After the NodeMaintenance CR is deleted: NHC reaches `Remediating` within
  the window, the node's TestRemediation CR exists, and NHC holds the lease.
- After kubelet restart: node Ready, NHC `Enabled`, node lease released.
- The timeline report entry records: notReadyObserved, negativeWindowEnd,
  nmDeleted, remediatingObserved, nodeReadyAgain, handoverLatency.
- Cleanup finishes: the test's NHC and NodeMaintenance CRs are gone, the
  worker is Ready/uncordoned/untainted, fixture objects this run created are
  removed, and the pre-existing NHC CRs are restored.

On a build where NMO does not hold the lease, step 3 fails. On a build where
NHC ignores the lease, step 8 fails (NHC starts remediating inside the
window).

## 8. Failure / known issues

None.

The NHC lease-holder identity is matched by substring
(`NodeHealthCheck-<CR name>`), as in the Python reference; the observed value
is logged on change so the first live run can confirm the exact format before
the match is tightened to equality.

## 9. Cleanup

- `DeferCleanup` (It level, registered before anything disruptive) deletes the
  test's NHC CR, then the NodeMaintenance CR, then restarts kubelet if the
  spec attempted to stop it, then waits for node recovery with the
  reboot-scale budget. Every step is best-effort and surfaces an unconfirmed
  result via `AddReportEntry`.
- `DeferCleanup` (BeforeAll level) tears down the TestRemediation fixture
  objects this run created — pre-existing objects are left in place — and
  restores the pre-existing NodeHealthCheck CRs snapshotted before deletion.
- Cleanup ordering is LIFO: node recovery runs before fixture teardown, which
  runs before NHC restore.
- All deletions use `wait.PollUntilContextTimeout` with warning logging;
  none of them can fail the suite.

## 12. Implementation sketch

```go
It("Verify NHC does not remediate a worker node leased by NMO and remediates it once maintenance ends",
    reportxml.ID("65651"),
    func() {
        DeferCleanup(func() {
            recoverLeaseTestNode(targetNodeName, nmCRName, nmoparams.NHCLeaseCRName, kubeletStopped)
        })

        By("Creating NodeMaintenance CR %s for node %s")
        // ... assertMaintenanceSucceeded, assertMaintenanceLease(true)

        By("Verifying NHC stays Enabled and does not take the lease for %s while NMO holds it")
        Consistently(func() (bool, error) {
            held, err := leaseWindowHolds(ctx, nodeName, nhcName)
            if err != nil {
                return false, TryAgainAfter(nmoparams.DefaultPollInterval).Wrap(err)
            }

            return held, nil
        }, nmoparams.NHCLeaseRemediationWindow, nmoparams.DefaultPollInterval).Should(BeTrue(),
            "NHC must stay Enabled, the lease holder must stay %s and no TestRemediation CR "+
                "may exist while NMO maintains node %s",
            nmoparams.LeaseHolderIdentity, nodeName)

        By("Deleting NodeMaintenance CR %s and waiting for removal")
        // positive control: same node, kubelet still down, must remediate
    })
```

The TestRemediation fixture (CRDs, template, RBAC) mirrors
`setupTestRemediationResources` from the NHC suite, which is package-private
there. Shared helpers reused from the NMO suite:
`selectSchedulableWorkerExcluding`, `isCRDInstalled`,
`deleteObjectBestEffortWithTimeout`, `waitForNodeRecoveryWithTimeoutBestEffort`,
`deleteNMsForNode`, `assertMaintenanceLease`, `deleteAndWaitForNMCR`,
`nmoControllerPod`; from `tests/internal/helpers`: `StopKubeletSSH`,
`StartKubeletSSHWithRetry`, `WaitForNodeReady`, `SSHBastionNodes`.
