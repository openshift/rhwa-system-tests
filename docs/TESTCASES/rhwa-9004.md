## 2. Summary

The WAO manager answers the NMO admission entry. This test sends `NodeMaintenance` requests with server-side dry-run while the NMO operand is `Disabled`, and again while it is `Enabled`. While NMO is `Disabled` it also stores one `NodeMaintenance`, to check the rules that compare a request with a stored object. No node enters maintenance.

## 3. Scope

- **In scope**: NMO rules NMO-1, NMO-2, NMO-4 and the permitted case of NMO-3 of `docs/wao-webhooks-test-plan.md`. The control plane request shows that the WAO ServiceAccount can read the Node, the etcd PodDisruptionBudget and the etcd guard Pods.
- **Out of scope**:
  - **The operand controllers.** Remediation, fencing and maintenance belong to the operator
    suites. This spec stores no remediation request and starts no maintenance.
  - **SBR admission.** The SBR operand serves its own webhooks.
  - **CRD schema validation.** A request that the API server rejects before admission does not
    reach a webhook. The operator suites cover those cases.
  - **The etcd quorum rejection (NMO-3).** It needs a control plane node in maintenance. Spec 46790 of
    `tests/nmo-operator` covers it.
  - **Rule NMO-2 with a real maintenance.** Spec 29630 of `tests/nmo-operator` covers it with a node drain.

## 5. Preconditions

Asserted in `BeforeAll`:

1. `NodeMaintenance` `wao-webhook-test-nm` does not exist. An object from an earlier run is deleted, and
   the spec waits until it is gone.
2. No node has the name `wao-webhook-test-no-such-node`.

The cluster needs one worker node and one control plane node. The spec fails if one of them is absent.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("9004")` runs and passes.
- Each request gets the answer in the table.
- The worker node of the stored `NodeMaintenance` stays schedulable.
- The NMO operand is enabled only after the stored `NodeMaintenance` is gone.
- Cleanup finishes: the `NodeMaintenance` is gone, and `spec.components.nodeMaintenance.enabled` has the value
  of the start.

## 9. Cleanup

- `DeferCleanup` removes the stored `NodeMaintenance`, also after a failure, and tolerates `IsNotFound`.
- `DeferCleanup` sets the NMO operand to the intent of the start, with one condition: if the stored
  `NodeMaintenance` still exists, NMO stays `Disabled` and the log says so. An enabled NMO manager drains
  the node of a stored `NodeMaintenance`.
- `AfterAll`: none.
- Manual recovery: `oc delete nodemaintenance wao-webhook-test-nm`, then enable NMO again if it was enabled.
