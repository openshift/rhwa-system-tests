## 2. Summary

WAO serves the admission webhooks of FAR, NHC, NMO and SNR from its own manager. This test reads the webhook configurations of the cluster and checks that the ten entries exist with the correct rule, `failurePolicy` and timeout, that each entry calls the WAO Service, and that no other Service intercepts the same resources.

## 3. Scope

- **In scope**: the registration of the ten entries in `waoparams.WebhookEntries`; their `clientConfig`, CA bundle, `sideEffects`, rule, `failurePolicy` and `timeoutSeconds`; the ready endpoints of the WAO Service; `status.components[].admissionReady` of the four operands.
- **Out of scope**:
  - **The answers of the webhooks.** RHWA-9002 to RHWA-9005 send requests and check the answers.
  - **The behavior when the listener does not answer.** RHWA-9006 covers that.
  - **SBR admission.** The SBR operand registers its own entries. They call a different Service and
    intercept different resources, so this spec ignores them.
  - **OLM v1 and a direct install.** The Service name in `waoparams.WebhookServiceName` is the name that
    classic OLM gives.

## 6. Test steps

| # | Step (`By` text) | Expected result |
| - | ---------------- | --------------- |
| 1 | `Verifying the WorkloadAvailabilityConfig singleton exists` | `cluster` is readable |
| 2 | `Listing every webhook entry on the cluster` | The two list requests succeed |
| 3 | `Verifying each expected entry calls the WAO Service with its failurePolicy, operations and timeout` | Each of the ten entries is served by the WAO Service exactly one time, with the listed type, group, resource, operations, `failurePolicy` and `timeoutSeconds` |
| 4 | `Verifying the WAO Service serves no entry outside the expected list` | No other entry calls the WAO Service |
| 5 | `Verifying each WAO entry has a CA bundle, one rule and no side effects` | `caBundle` is not empty, the entry has one rule, `sideEffects` is `None` |
| 6 | `Verifying no other Service intercepts a resource that WAO serves` | No entry of a different Service has a rule for one of the seven resources |
| 7 | `Verifying the WAO Service has one ready endpoint for each WAO manager replica` | Ready endpoints = `spec.replicas` = `status.readyReplicas` within `waoparams.OperandAvailableTimeout` |
| 8 | `Verifying WAO reports admissionReady for operand <operand>` | Runs four times, for `fenceAgentsRemediation`, `nodeHealthCheck`, `nodeMaintenance` and `selfNodeRemediation`. `admissionReady` is `true` |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("9001")` runs and passes.
- The WAO Service `workload-availability-operator-controller-manager-service` serves exactly the ten
  entries of `waoparams.WebhookEntries`.
- `vselfnoderemediation.kb.io` is the only entry with `failurePolicy: Ignore`. The other nine have `Fail`.
- `vnodemaintenance.kb.io` has `timeoutSeconds: 15`. The other nine have `10`.
- No entry of a different Service has a rule for `fenceagentsremediations`,
  `fenceagentsremediationtemplates`, `nodehealthchecks`, `nodemaintenances`, `selfnoderemediations`,
  `selfnoderemediationconfigs` or `selfnoderemediationtemplates`.
- Cleanup finishes: the spec creates nothing, so the cluster does not change.

## 11. Running it standalone

```bash
ginkgo -v --label-filter="component:webhook && operator:wao" \
    --focus="RHWA-9001" ./tests/wao-operator/...
```

The webhook run script selects the spec together with the other webhook specs:

```bash
make run-webhook-tests WEBHOOK_TARGET=wao
```

Watch the cluster while it runs:

```bash
watch -n 5 -d tools/watch/webhook-watch.sh   # Linux, or macOS with `brew install watch`
tools/watch/webhook-watch.sh --loop          # anywhere, no `watch` needed
```

`webhook-watch.sh` shows five blocks: the webhook entries that call a Service in the namespace, the
endpoints of the WAO Service, the operand rows (`DESIRED`, `PHASE`, `ADMIT`), the stored objects of the
admission kinds, and the pods. For this spec nothing must change in any block: the spec only reads.
