## 2. Summary

The WAO manager answers the NHC admission entry for create, update and delete. This test sends `NodeHealthCheck` requests with server-side dry-run while the NHC operand is `Disabled`, and again while it is `Enabled`. While NHC is `Disabled` it also stores one paused `NodeHealthCheck` with a test status, to check the update and delete rules that apply during a remediation.

## 3. Scope

- **In scope**: NHC rules NHC-1 to NHC-11 of `docs/wao-webhooks-test-plan.md`. The duplicate kind rule is checked for the rejected case (MDR templates) and for the permitted case (SNR templates that the SNR defaulter of WAO annotates). The update and delete rules are checked with a status that the spec writes.
- **Out of scope**:
  - **The operand controllers.** Remediation, fencing and maintenance belong to the operator
    suites. This spec stores no remediation request and starts no maintenance.
  - **SBR admission.** The SBR operand serves its own webhooks.
  - **CRD schema validation.** A request that the API server rejects before admission does not
    reach a webhook. The operator suites cover those cases.
  - **The update and delete rules with a real remediation.** Specs 60865 and 56600 of `tests/nhc-operator`
    cover them with a kubelet stop. This spec writes the status entry itself. That is possible only while
    NHC is `Disabled`, because the NHC manager removes an entry that it did not write.
  - **Template kinds that are not in the WAO bundle.** Spec 74932 of `tests/nhc-operator` covers a
    vendor kind and gives the WAO ServiceAccount the `list` permission.
  - **The NHC status report of WAO** for a blocked `NodeHealthCheck`.

## 5. Preconditions

Asserted in `BeforeAll`:

1. `NodeHealthCheck` `wao-webhook-test-nhc` does not exist. An object from an earlier run is deleted (the
   status entry is removed first), and the spec waits until it is gone.
2. Templates `wao-webhook-test-snr-template-1` and `-2` do not exist. Templates from an earlier run are
   deleted.

Each `SelfNodeRemediationTemplate` on the cluster must have the annotation
`remediation.medik8s.io/multiple-templates-support`. That is true for each template that was created
through the SNR defaulter. The spec does not assert it before the run: a template without the annotation
makes the permitted case of the duplicate kind rule fail, and the failure names the rule.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("9003")` runs and passes.
- Each request gets the answer in the table. Each denial names `vnodehealthcheck.kb.io`.
- The stored `NodeHealthCheck` exists only while NHC is `Disabled`. It selects no node and has a pause request.
- Cleanup finishes: the `NodeHealthCheck` and the two templates are gone, and
  `spec.components.nodeHealthCheck.enabled` has the value of the start.

## 9. Cleanup

- `DeferCleanup` removes the stored `NodeHealthCheck` (status entry first) and the two templates, also after
  a failure, and tolerates `IsNotFound`.
- `DeferCleanup` sets the NHC operand to the intent of the start.
- `AfterAll`: none.
- Manual recovery, if a run stops between the status write and the delete:

  ```bash
  oc patch nodehealthcheck wao-webhook-test-nhc --subresource=status --type=merge \
      -p '{"status":{"unhealthyNodes":null}}'
  oc delete nodehealthcheck wao-webhook-test-nhc
  ```

## 11. Running it standalone

```bash
ginkgo -v --label-filter="component:webhook && operator:wao" \
    --focus="RHWA-9003" ./tests/wao-operator/...
```

The webhook run script selects the spec together with the other webhook specs:

```bash
make run-webhook-tests WEBHOOK_TARGET=nhc
```

Watch the cluster while it runs:

```bash
watch -n 5 -d tools/watch/webhook-watch.sh   # Linux, or macOS with `brew install watch`
tools/watch/webhook-watch.sh --loop          # anywhere, no `watch` needed
```

What must change: the `nodeHealthCheck` row goes `Disabled` → `Available` (and back, when it was
`Disabled` at the start). The two templates and the `NodeHealthCheck` appear in the stored objects block
and go before the operand is enabled. What must not change: `ADMIT` stays `true`, the entries block, and
no `SelfNodeRemediation` appears.
