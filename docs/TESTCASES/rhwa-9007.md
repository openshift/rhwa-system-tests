## 2. Summary

The admission listener is part of the WAO manager. This test deletes each WAO manager Pod and checks that the new Pods serve admission for the seven kinds again, and that the FAR agent inventory is collected again.

## 3. Scope

- **In scope**: the return of admission after each WAO manager Pod is replaced; `admissionReady` after the restart; the FAR agent inventory, which an init container of each new Pod reads from the FAR image.
- **Out of scope**:
  - **The answers during the restart.** The spec waits for the new Pods and does not assert an answer
    while they start. RHWA-9006 covers the answers when no replica answers.
  - **A restart of one replica** with the other replica in service.
  - **A node failure or a rescheduling of the WAO Pods.**

## 5. Preconditions

Asserted in `BeforeAll` (the container is shared with RHWA-9006):

1. The `WorkloadAvailabilityConfig` singleton `cluster` exists.
2. `NetworkPolicy` `wao-webhook-test-deny-admission` does not exist.

The first seven steps of the `It` assert that admission answers before the restart.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("9007")` runs and passes.
- Each WAO manager Pod of the start is gone, and the Deployment has its replicas `Ready` again within
  `waoparams.AdmissionRecoveryTimeout`.
- `admissionReady` is `true` for the four operands.
- Each of the seven requests is admitted again, and the agent rule of FAR rejects `fence_incorrect`.
- Cleanup finishes: the spec stores nothing. The Deployment replaces the Pods.

## 9. Cleanup

- `DeferCleanup`: none. The `It` stores no object.
- `AfterAll`: none.
- Recovery: none is necessary. The Deployment creates the Pods again. If the new Pods do not start, read
  the `far-agent-inventory` init container: the image pull of the FAR manager image is its usual cause.

## 11. Running it standalone

```bash
ginkgo -v --label-filter="component:webhook && operator:wao" \
    --focus="RHWA-9007" ./tests/wao-operator/...
```

The webhook run script selects the spec together with the other webhook specs:

```bash
make run-webhook-tests WEBHOOK_TARGET=wao
```

Watch the cluster while it runs:

```bash
watch -n 5 -d tools/watch/webhook-watch.sh   # Linux, or macOS with `brew install watch`
tools/watch/webhook-watch.sh --loop          # anywhere, no `watch` needed
```

What must change: the two `workload-availability-operator-controller-manager` pods get new names and a new
age, and the endpoints block shows the new Pods. What must not change: the webhook entries block, and the
operand rows (an enabled operand stays `Available`: WAO does not remove an operand when its own manager
restarts).
