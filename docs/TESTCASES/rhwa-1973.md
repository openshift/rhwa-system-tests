## 2. Summary

Verify that the installed NHC controller releases an indefinitely delayed
remediation after manual health confirmation, removes the annotation using its
own deployed Node permissions, and returns to Enabled.

## 3. Scope

- **In scope**: RHWA-1846, a real controller and API server enforcing RBAC,
  `healthyDelay: -1s`, remediation deletion, annotation removal, and recovery status.
- **Out of scope**: FAR fencing, SNR reboot, kubelet failure, and an operator
  upgrade. Unlike the ticket's FAR scenario, this test uses a harmless dedicated
  remediation kind to exercise the same NHC cleanup path without fencing a node.
  Its temporary RBAC grants access only to that test API, never to core Nodes.
  The Node's actual Ready condition and boot ID must remain unchanged.
- **Assertions**: Kubernetes objects, Node annotations, and NHC status determine
  pass/fail. Controller logs are not required or parsed.

## 5. Preconditions

`BeforeAll` verifies the NHC deployment is Ready, removes only leftovers carrying
this test's ownership marker, and skips if another NHC configuration exists.
Unmarked objects using this test's reserved names are never deleted or adopted.
The worker must have no pre-existing manual-health annotation or test condition.
The test snapshots the worker UID and boot ID and claims it with a dedicated label.

## 6. Test steps

| # | Step (`By` text) | Expected result |
| --- | --- | --- |
| 1 | Verifying NHC is Ready and removing owned leftovers | Ready controller and no stale test-owned resources |
| 2 | Selecting an isolated Ready worker | No competing NHC and an eligible worker |
| 3 | Creating a harmless remediator and an indefinitely delayed NHC | Dedicated test CRDs and RBAC, one-node NHC reaches Enabled |
| 4 | Triggering remediation with a test-only Node condition | NHC creates exactly one owned test remediation and becomes Remediating |
| 5 | Recovering the test condition and verifying manual confirmation is required | Worker stays Ready, same remediation UID remains for 30 seconds |
| 6 | Manually confirming health and waiting for controller cleanup | NHC deletes the remediation, removes the annotation, and becomes Enabled |
| 7 | Verifying the worker and unrelated metadata were preserved | Same Node UID and boot ID, Ready remains True, ownership label unchanged |
| 8 | Restoring the worker and removing test resources | Test condition and annotation gone, all owned resources deleted |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1973")` runs and passes.
- The real NHC creates a remediation within `nhcparams.ManualHealthTimeout`.
- After the test condition becomes False, the same remediation remains and NHC
  stays Remediating for `nhcparams.ManualHealthHoldDuration`, without a manual
  confirmation annotation.
- After manual confirmation, the remediation is absent, the annotation is absent,
  observedNodes and healthyNodes are both 1, unhealthyNodes is empty, and NHC is
  Enabled within `nhcparams.ManualHealthTimeout`.
- No test helper removes the annotation before this assertion. Cleanup's admin
  removal happens only after the result is established, including on failure.
- The Node stays Ready, with the original UID and boot ID. Its unrelated metadata
  is preserved by targeted patches.
- Cleanup completes within `nhcparams.ManualHealthCleanupTimeout`.

## 8. Failure / known issues

[RHWA-1846](https://redhat.atlassian.net/browse/RHWA-1846) was fixed by
[node-healthcheck-operator#465](https://github.com/medik8s/node-healthcheck-operator/pull/465).
The original cleanup used Node Update without the matching permission. The final
fix uses Merge Patch and grants `patch` on Nodes, so this test does not require
an obsolete `update` permission.

A build lacking its cleanup permission should fail annotation-removal and status
recovery assertions. Fixed-build validation and any actual pre-fix comparison
must be reported separately. Neither a dry run nor a fake-client test is proof
of live RBAC enforcement. No known-bug gate is needed for a fixed build.

## 9. Cleanup

`DeferCleanup` restores only this test's condition and manual-health annotation,
deletes its owned harmless remediations, waits for NHC to leave Remediating,
and deletes the test NHC before deleting its template, binding, role, and CRDs.
The Node's ownership label is removed last, so interrupted cleanup remains
identifiable on the next run. Missing resources are tolerated and UID
preconditions protect against deleting replacements.

Cleanup also runs on assertion failure. It never replaces the full Node metadata
or conditions, strips product finalizers, or changes the controller's Node RBAC.
`BeforeAll` uses the same cleanup for marked leftovers. No `AfterAll` resources.

## 12. Implementation sketch

One serial, ordered spec in `manual_health_confirmation.go`. Existing NHC
builders, deployment readiness, CRD establishment, and phase helpers are reused.
Private fixture helpers in the same file create a dedicated harmless remediator,
apply a strategic merge patch for the test condition, assert lifecycle state,
and clean up only owned resources. The test does not add a new shared framework.

Local validation on 2026-10-28: formatting, lint, unit tests, document and Jira
checks passed. The focused dry run selected exactly this one spec. Live validation
and a pre-fix comparison have not been performed.
