## 2. Summary

Nine WAO admission entries have `failurePolicy: Fail` and one, `vselfnoderemediation.kb.io`, has `Ignore`. This test isolates the WAO admission listener with a `NetworkPolicy` and checks that the API server rejects a valid request for each kind with `Fail`, and admits a `SelfNodeRemediation`.

## 3. Scope

- **In scope**: the effect of `failurePolicy` for the seven kinds when no WAO replica answers, and the return of admission when the listener is reachable again.
- **Out of scope**:
  - **The answers of the webhooks.** RHWA-9002 to RHWA-9005 cover them.
  - **A WAO Pod that is not running.** RHWA-9007 covers a restart. This spec keeps the Pods `Ready` and
    blocks only the network path.
  - **The delete entries** of `nodehealthchecks` and `selfnoderemediationconfigs`. A delete needs a stored
    object.
  - **The validating entries of the three kinds that also have a mutating entry.** The API server calls the
    mutating entry first, so the failure names that entry.
  - **A network plugin that does not apply a NetworkPolicy to traffic from the API server.** The spec then
    fails in the step that waits for the outage.

## 5. Preconditions

Asserted in `BeforeAll`:

1. The `WorkloadAvailabilityConfig` singleton `cluster` exists.
2. `NetworkPolicy` `wao-webhook-test-deny-admission` does not exist. A policy from an earlier run is
   deleted, and the spec waits until it is gone.

The first seven steps of the `It` assert that admission answers before the outage. The cluster needs one
worker node for the `NodeMaintenance` request.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("9006")` runs and passes.
- With the listener isolated, the six kinds with `Fail` get an internal error of a failed webhook call, and
  the `SelfNodeRemediation` request is admitted.
- The WAO manager Pods stay `Ready` during the outage.
- After the policy is gone, each of the seven requests is admitted again within
  `waoparams.AdmissionRecoveryTimeout`.
- Cleanup finishes: the `NetworkPolicy` is gone.

## 9. Cleanup

- `DeferCleanup` removes the `NetworkPolicy`, also after a failure, and tolerates `IsNotFound`.
- `AfterAll`: none.
- Manual recovery, if a run stops while the policy exists:
  `oc -n openshift-workload-availability delete networkpolicy wao-webhook-test-deny-admission`.
  Admission for nine entries fails until the policy is gone.

## 11. Running it standalone

```bash
ginkgo -v --label-filter="component:webhook && operator:wao" \
    --focus="RHWA-9006" ./tests/wao-operator/...
```

The webhook run script selects the spec together with the other webhook specs:

```bash
make run-webhook-tests WEBHOOK_TARGET=wao
```

Watch the cluster while it runs:

```bash
watch -n 5 -d tools/watch/webhook-watch.sh   # Linux, or macOS with `brew install watch`
tools/watch/webhook-watch.sh --loop          # anywhere, no `watch` needed
```

What must change: `networkpolicy.networking.k8s.io/wao-webhook-test-deny-admission` appears in the stored
objects block for approximately 2 minutes. What must not change: the WAO pods stay `1/1`, the endpoints
stay `true`, and the `ADMIT` column stays `true` (the readiness check of WAO uses the local listener, so
it does not show a blocked network path).
