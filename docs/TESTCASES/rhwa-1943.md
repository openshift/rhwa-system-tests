## 2. Summary

When the NHC console plugin is deployed with `readOnlyRootFilesystem: true` in the
container securityContext, the `node-remediation-console-plugin` pod must start
successfully and remain Running. Before RHWA-527, the pod entered
CrashLoopBackOff because the startup scripts tried to write to the root filesystem
at `/opt/app-root/etc/passwd` and `/var/log/nginx`.

## 3. Scope

- **In scope**: The console plugin pod reaches and holds Running state with
  `readOnlyRootFilesystem: true` active in its container securityContext; the
  field is present and set to `true` in the pod spec as deployed by NHC.
- **Out of scope**: Console plugin API serving (covered by the upstream
  `nhc_console_e2e_test.go`); the NHC controller-manager container security
  context (covered by `post_deployment.go` test `reportxml.ID("89632")`);
  clusters without the console plugin installed — the test skips gracefully on
  those.

broken rollout is still caught.

## 5. Preconditions

1. NHC operator installed via OLM, controller deployment Ready (asserted in
   `BeforeAll` of the enclosing `Describe` block).
2. If the console plugin is deployed, its pods must not be stuck in
   `CrashLoopBackOff` from a prior failed run; the readiness `Eventually` in
   step 2 surfaces that as a timeout rather than a false pass.

## 6. Test steps

| # | Step (`By` text)                                                             | Expected result                                                                                        |
| - | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1 | `Checking whether the NHC console plugin is deployed`                        | Deployments are listed by `app.kubernetes.io/component=node-remediation-console-plugin`; test skips with an actionable message when no Deployment matches |
| 2 | `Waiting for every console plugin pod to be Running and Ready`               | Every pod selected by the same label reaches phase `Running` with all container statuses `Ready` within `medik8sparams.DefaultTimeout`; a `CrashLoopBackOff` times out and fails. The verified pod set is captured for step 3 |
| 3 | `Verifying console plugin container has readOnlyRootFilesystem=true`         | Reusing the pod set verified in step 2, each pod contains a container named `node-remediation-console-plugin` (asserted present), with a non-nil `SecurityContext` and `ReadOnlyRootFilesystem` explicitly set to `true` |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1943")` runs and passes.
- At least one Deployment matches the console plugin label selector (otherwise the
  test skips).
- Every selected pod reaches `Running` and `Ready` within
  `medik8sparams.DefaultTimeout` (this is the RHWA-527 regression signal).
- Each verified pod has a container named `node-remediation-console-plugin` with
  `securityContext.readOnlyRootFilesystem == true`.
- Cleanup finishes: no cluster resources were created by this test; nothing to
  remove.
