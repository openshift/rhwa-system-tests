This is the Block-mode counterpart of the Filesystem split-brain test
(`tests/sbr-operator/tests/split_brain.go`, OCP-88877). It carries its own
`reportxml.ID("1934")` rather than sharing the Filesystem test's ID, so the two
runs report as distinct results — the same pattern the block node hang test
(RHWA-1931) follows against OCP-88738.

## 2. Summary

One worker node running SBR in Block volume mode on Ceph RBD is cut off from
Ceph storage while its peers keep their access. SBR must fence exactly that node
— detect its stalled heartbeat, let NHC create a `StorageBasedRemediation` CR,
prove the node dead from storage, taint and reboot it — and leave every witness
node untouched: no witness is flagged unhealthy, remediated, rebooted, or
self-fenced. In Block mode the slot geometry decides which node a fence lands on
and whose heartbeat is read for death, so this test guards that geometry.

## 3. Scope

- **In scope**: that fencing in Block mode on Ceph RBD hits only the
  storage-isolated node — storage-based detection (`SBRStorageUnhealthy`), NHC
  creating the CR, peer fencing, `FencingSucceeded`/`Succeeded` proven *after*
  the victim's last heartbeat, the `out-of-service` taint, reboot recovery — while
  every witness node stays Ready, schedulable, on its original boot-id, and with
  an unchanged `sbr_self_fenced_total`.
- **Out of scope**:
  - The same split-brain scenario on RWX **Filesystem** storage
    (`split_brain.go`, OCP-88877).
  - The full single-victim remediation path without witnesses
    (`block_storage_node_hang.go`, RHWA-1931).
  - The watchdog self-fencing path when a node loses storage entirely
    (`storage_loss_watchdog.go`, OCP-88880).
  - Recovery from a *transient* Ceph RBD partition without fencing
    (`block_storage_transient_partition.go`, RHWA-1924).
  - Block device on-disk layout correctness (`block_storage_inspection.go`,
    RHWA-1926) and heartbeat stability under load (`block_storage_heartbeat_load.go`,
    RHWA-1925).

## 4. Environment

| Requirement  | Value                                                                       |
| ------------ | --------------------------------------------------------------------------- |
| Cluster      | OCP, multi-node, ≥ 3 schedulable workers (one victim not hosting an SBR controller pod + ≥ 2 witnesses) |
| Topology     | any                                                                         |
| Platform     | `platform:any`                                                              |
| Storage      | Ceph RBD StorageClass, RWX, `volumeMode: Block` (provisioner contains `rbd.csi.ceph.com`) |
| Network      | connected or disconnected                                                   |
| Namespace    | `openshift-workload-availability` (`medik8sparams.OperatorNs`)              |
| Destructive? | yes — one worker node is cut off from Ceph, fenced, and rebooted            |

Environment variables:

```bash
export KUBECONFIG=/absolute/path/to/kubeconfig
export ECO_TEST_FEATURES=sbr-operator
export ECO_TEST_LABELS='operator:sbr && component:remediation'
# Optional:
export SBR_RBD_STORAGE_CLASS=<ceph-rbd-storageclass>   # overrides RBD auto-discovery
export SBR_INJECTOR_IMAGE=<ubi9 image with nsenter+iptables>  # required in disconnected clusters
```

- `SBR_RBD_STORAGE_CLASS` — the Ceph RBD StorageClass. When unset, a StorageClass
  whose provisioner contains `rbd.csi.ceph.com` is auto-discovered; the test
  **skips** when none exists.
- `SBR_INJECTOR_IMAGE` — image for the privileged injector pod; must ship
  `nsenter` and `iptables`. Defaults to `registry.access.redhat.com/ubi9/ubi:latest`;
  must be mirrored and set in disconnected clusters.

## 5. Preconditions

1. The `NodeHealthCheck` CRD is installed (otherwise the test skips).
2. No pre-existing `NodeHealthCheck` from a prior run of this test
   (`nhc-sbr-block-split-brain`) — it is deleted and waited out in `BeforeAll`.
3. No other `NodeHealthCheck` remediates through the SBR template
   (`requireNoSBRNodeHealthCheck`), which would fence a node independently.
4. Self Node Remediation is not running (SNR and SBR cannot share the watchdog).
5. At least 3 schedulable worker nodes, at least one of which hosts no SBR
   controller pod; that one is the victim, so the fencing reboot does not take
   the operator down mid-test. Every other schedulable worker is a witness.
   Otherwise the test skips.
6. iptables is usable in the victim node's host namespaces (probe pod);
   otherwise the test skips.
7. A Ceph RBD `volumeMode: Block` StorageClass exists.
8. The Block device-init Job for the test SBRC completes successfully and the
   agent DaemonSet becomes ready.
9. The SBRC reports `status.storageValidation.concurrentWriteable=true`.
10. An observer agent pod on a witness node is available to read the shared
    device.

## 6. Test steps

| #  | Step (`By` text)                                                                                     | Expected result                                                                 |
| -- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 1  | Recording the victim node's boot-id before the partition                                             | Pre-partition victim boot-id read                                               |
| 2  | Asserting SBRStorageUnhealthy is not True on the victim node                                         | Victim's `SBRStorageUnhealthy` is absent, False or Unknown (not True)           |
| 3  | Recording every witness node's boot-id and its agent's sbr_self_fenced_total counter and restart count | Each witness's boot-id, agent pod name, self-fence counter and restart count recorded |
| 4  | Starting a privileged injector pod that blocks Ceph ports on the victim node                         | OUTPUT REJECT rules for ports 3300, 6789, 6800–7300 applied on the victim only   |
| 5  | Waiting for SBRStorageUnhealthy=True (reason HeartbeatTimeout) on the victim node                    | A peer sets `SBRStorageUnhealthy=True` with reason `HeartbeatTimeout`            |
| 6  | Looking up the victim's heartbeat node ID in the node map and recording its last heartbeat           | Victim's node ID found in the on-device node map; the slot at index nodeID-1 carries that node ID; its last heartbeat timestamp recorded |
| 7  | Consistently asserting for 60s that no witness becomes unhealthy or gets an SBR CR                    | For 60s no witness reaches `SBRStorageUnhealthy=True` and none has an SBR CR     |
| 8  | Waiting for NHC to create a StorageBasedRemediation CR for the victim node                           | `StorageBasedRemediation/<victim>` exists                                        |
| 9  | Waiting for FencingSucceeded=True and Succeeded=True on the victim's StorageBasedRemediation CR       | Both conditions reach True (CR re-pulled by name on every poll)                  |
| 10 | Asserting the FencingSucceeded transition happened after the victim's last heartbeat                  | `FencingSucceeded` lastTransitionTime (from the CR seen in step 9) is later than the recorded heartbeat |
| 11 | Asserting the victim node carries the out-of-service taint                                            | Victim has `node.kubernetes.io/out-of-service`                                   |
| 12 | Waiting for the victim node's boot-id to change (confirms it actually rebooted)                       | Victim boot-id differs from the pre-partition boot-id                           |
| 13 | Waiting for the victim node to come back Ready                                                        | Victim reports `Ready=True`                                                      |
| 14 | Asserting every witness node is Ready, schedulable and keeps its original boot-id                     | Each witness is Ready, schedulable, same boot-id; same agent pod, restart count and `sbr_self_fenced_total` unchanged |
| 15 | Waiting for the victim node's agent pod to be Ready again                                             | This SBRC's agent pod on the victim reaches `PodReady=True`                      |
| 16 | Consistently asserting that the victim is not fenced again (stable boot-id and Ready)                 | For 90s the victim keeps its new boot-id and stays `Ready=True`                  |
| 17 | Waiting for NHC to delete the StorageBasedRemediation CR                                              | `StorageBasedRemediation/<victim>` is gone (`IsNotFound`)                        |
| 18 | Asserting the victim node is schedulable again and the out-of-service taint is gone                   | Victim is schedulable and carries no `out-of-service` taint                      |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1934")` runs and passes.
- After the partition, a peer reports the victim `SBRStorageUnhealthy=True`
  (reason `HeartbeatTimeout`) within `StorageInjectionTimeout`.
- For `SplitBrainHealthyNodeCheckDuration` (60s) no witness is flagged
  `SBRStorageUnhealthy=True` and no witness has a `StorageBasedRemediation` CR.
- NHC creates exactly one `StorageBasedRemediation` named after the victim; it
  reaches `FencingSucceeded=True` **and** `Succeeded=True` within
  `FencingProvenTimeout`, with the `FencingSucceeded` transition later than the
  victim's last heartbeat on the device, and the victim carries the
  `node.kubernetes.io/out-of-service` taint.
- Every witness stays Ready, schedulable, keeps its original boot-id, and its
  agent is the same pod with an unchanged restart count and
  `sbr_self_fenced_total`.
- The victim returns `Ready` with a changed boot-id, its agent pod reaches
  `PodReady=True`, and for `BlockNoFencingCheckDuration` (90s) it keeps that
  boot-id and stays Ready.
- NHC deletes the CR, and the victim becomes schedulable with the
  `out-of-service` taint removed.
- Cleanup finishes: the NHC, SBRC and injector pod are gone, no
  `StorageBasedRemediation` remains, the victim is uncordoned, and any leftover
  Ceph REJECT rule is flushed.

## 8. Failure / known issues

None.

Two design notes, neither a known bug: `FencingInProgress` is deliberately never
asserted, because the 60s fencing window and the 60s heartbeat-staleness threshold
are both hardcoded, so the condition flaps and a `FencingFailed` event is a normal
retry rather than a failure; and the victim's CR is looked up by node name on
every poll because it can be deleted and recreated mid-remediation when
`SBRStorageUnhealthy` cycles to `Unknown`.

## 9. Cleanup

- `DeferCleanup` removes the injector pod and flushes any Ceph REJECT rule left
  on the victim node (`flushCephRBDRules` deletes exactly the rules the injector
  inserted).
- `AfterAll` removes the `NodeHealthCheck`, deletes the injector pod, flushes
  leftover Ceph rules on the victim, uncordons the victim if still cordoned,
  force-removes any `StorageBasedRemediation` for the victim and witnesses, and
  deletes the SBRC (waiting for it to be gone). All tolerate `IsNotFound`.
- Recovery (uncordon, iptables flush) runs even when the spec failed mid-way.
- `BeforeAll` pre-cleans the test's own stale NHC and SBRC from a prior run and
  waits for them to be fully gone before recreating.
