## 2. Summary

SNR's control plane self-diagnostics check the local kubelet at
`https://<address>:10250/pods`. Before the fix that address was always the node's
`metadata.name`, so on clusters where node names are not DNS-resolvable the check always
failed and the node falsely self-remediated. PR #331 adds
`SelfNodeRemediationConfig.spec.preferredAddressTypes`, which selects addresses from
`node.status.addresses` instead. This test proves the new field is validated, reaches the
agent DaemonSet, and leaves a healthy cluster un-remediated.

## 3. Scope

- **In scope**:
  - CRD enum validation of `spec.preferredAddressTypes`: all six documented values
    (`NodeName`, `Hostname`, `InternalDNS`, `ExternalDNS`, `InternalIP`, `ExternalIP`) are
    accepted, and anything else is rejected by the API server.
  - The default: with the field unset the agent DaemonSet renders
    `PREFERRED_ADDRESS_TYPES=""`, which the agent treats as `["NodeName"]` — the
    backward-compatible behaviour PR #331 promises.
  - Rendering: a configured list reaches the agent container as a comma-separated
    `PREFERRED_ADDRESS_TYPES` env var **in the configured order**, since order is the
    fallback precedence.
  - Rollout: changing the field restarts every agent pod and all of them return Ready,
    including those on control plane nodes. This matters because the API doc states
    addresses "are currently only read on startup, so a pod restart is required".
  - No false self-remediation: across an observation window after the change, no
    `SelfNodeRemediation` CR appears for any control plane node and no control plane node
    changes its boot ID.
  - A positive control that the configured address type is actually usable: the kubelet
    answers on `https://<address>:10250/` for each control plane node's address of the
    configured type.
- **Out of scope**:
  - **The address-selection algorithm itself** — fallback to later types, ignoring
    addresses of other types, trying every address of a type, IPv6 via `net.JoinHostPort`,
    and the unresolvable-node-name case. PR #331 added
    `internal/controlplane/manager_test.go` upstream, which covers all seven of these with
    a stub kubelet. Re-testing them on a live cluster would add cost and no coverage.
  - **Driving a control plane node into `isDiagnosticsPassed()`.** See the note below; this
    is the main reason the test case is shaped the way it is.
  - Reproducing the original bug by making node names unresolvable. OCP node names resolve
    by construction, and breaking cluster DNS to prove a negative is destructive and would
    not isolate SNR's behaviour from everything else that would fail.
  - Worker node behaviour. `preferredAddressTypes` is read only on the control plane
    self-diagnostics path.
  - The `endpointHealthCheckUrl` half of `isDiagnosticsPassed()`, which PR #331 does not
    touch.

### Why the self-diagnostics path is not driven end to end

`isDiagnosticsPassed()` — the only caller of the kubelet check — is reached from
`controlplane.Manager.IsControlPlaneHealthy` for exactly two worker-peer responses:

| Worker peer response | What `IsControlPlaneHealthy` returns |
| -------------------- | ------------------------------------- |
| `HealthyBecauseNoPeersWereFound` | `didDiagnosticsPass && canOtherControlPlanesBeReached` |
| `HealthyBecauseMostPeersCantAccessAPIServer` | `didDiagnosticsPass` |

Neither is a usable system-test fixture. The first ANDs the diagnostics result with control
plane peer reachability, so on a cluster with no worker peers an isolated control plane node
reboots whatever the kubelet check says — the diagnostics outcome is unobservable. The second
requires more than half the worker peers to report API-server errors simultaneously, which
cannot be arranged without breaking the cluster for unrelated reasons. Both paths also only
run after peer loss, which is itself destructive.

So the honest division is: the decision logic is unit-tested upstream, and this test case
covers the cluster-level contract — the field is validated, it reaches the agents in the
right form, the agents survive it, and nothing reboots. The last two are what a customer
hitting RHWA-1596 actually needs to be true before changing the setting.

## 5. Preconditions

Asserted in `BeforeAll`:

1. The SNR operator deployment is Ready and the default `SelfNodeRemediationConfig`
   (`self-node-remediation-config`) exists.
2. Every SNR agent DaemonSet pod is Running with all containers Ready.
3. The original value of `spec.preferredAddressTypes` is captured for restore. On a default
   install it is unset; the test must not assume that.
4. Every control plane node has at least one `InternalIP` in `status.addresses`; otherwise
   skip with a message naming the node.
5. No `NodeHealthCheck` selects control plane nodes. One could legitimately create a
   `SelfNodeRemediation` CR during the observation window and make step 10 fail for a reason
   unrelated to this fix, so the spec skips rather than reporting a false failure.
6. No `SelfNodeRemediation` CR exists for any control plane node.
7. The boot ID of every control plane node is recorded, for the no-reboot assertion.

## 6. Test steps

| #  | Step (`By` text)                                                                                   | Expected result                                                                            |
| -- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1  | Verifying the agent DaemonSet renders an empty PREFERRED_ADDRESS_TYPES by default                      | With the field unset, the agent container's `PREFERRED_ADDRESS_TYPES` env var is present and empty, which the agent treats as `["NodeName"]` |
| 2  | Rejecting a SelfNodeRemediationConfig with an invalid preferredAddressTypes value                      | Patching the SNRC with `["NotAnAddressType"]` is rejected by the API server with an enum validation error naming the field |
| 3  | Accepting every documented preferredAddressTypes value                                                 | Each of `NodeName`, `Hostname`, `InternalDNS`, `ExternalDNS`, `InternalIP`, `ExternalIP` is accepted when patched individually |
| 4  | Verifying the kubelet answers on the InternalIP of every control plane node                            | `https://<InternalIP>:10250/` returns an HTTP response (401 is success for this purpose — it proves the port is served), confirming the address type about to be configured is usable |
| 5  | Patching the SelfNodeRemediationConfig with preferredAddressTypes InternalIP and NodeName              | The patch is accepted and the SNRC spec reflects both values in order                       |
| 6  | Waiting for the agent DaemonSet to roll out after the configuration change                             | The DaemonSet's observed generation advances and all pods are Ready within `snrparams.DSPodRestartTimeout` |
| 7  | Verifying PREFERRED_ADDRESS_TYPES is rendered comma-separated in the configured order                  | The agent container env var equals exactly `InternalIP,NodeName` — order preserved, since it is the fallback precedence |
| 8  | Verifying every agent pod on a control plane node is Running and Ready                                 | No agent pod is in CrashLoopBackOff and every control plane node has a Ready agent pod      |
| 9  | Verifying no agent pod logs a kubelet service failure for the configured addresses                     | `kubelet service is down` is absent from every control plane agent pod's log for the window since the rollout |
| 10 | Consistently verifying no control plane node is remediated or rebooted                                 | For `snrparams.PreferredAddressNoRemediationDuration`, no `SelfNodeRemediation` CR exists for any control plane node and every control plane boot ID is unchanged |
| 11 | Restoring the original preferredAddressTypes and waiting for the DaemonSet to roll out                 | The SNRC returns to its captured original spec and all agent pods are Ready again           |

Step 9 is a weak assertion by design and is documented as such: on a healthy cluster the
self-diagnostics path never runs, so the message would be absent either way. It is kept
because it costs nothing and would catch an agent that somehow runs the kubelet check at
startup and fails it. Step 10 is the assertion that carries the regression value — it is what
would have failed on an affected cluster before PR #331.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1928")` runs and passes.
- With `preferredAddressTypes` unset, the agent container's `PREFERRED_ADDRESS_TYPES` env var
  is present and empty.
- An invalid address type is rejected by the API server; all six documented values are
  accepted.
- After patching to `["InternalIP", "NodeName"]`, the env var is exactly `InternalIP,NodeName`
  and the DaemonSet reaches full readiness within `snrparams.DSPodRestartTimeout`.
- Every control plane node has a Running, Ready agent pod with no restarts attributable to
  the configuration change.
- For `snrparams.PreferredAddressNoRemediationDuration` after the rollout, no
  `SelfNodeRemediation` CR exists for any control plane node and no control plane node's
  `status.nodeInfo.bootID` changes.
- Cleanup finishes: the SNRC's `preferredAddressTypes` is back to the value captured in
  `BeforeAll`, the DaemonSet has rolled out again, and all agent pods are Ready.

On a build without PR #331 this spec fails at step 2 or step 5: `preferredAddressTypes` does
not exist in the CRD schema, so the patch is rejected as an unknown field. That is the
simplest regression signal; the no-remediation assertion in step 10 is what protects the
behaviour once the field exists.

## 9. Cleanup

- `DeferCleanup` restores `spec.preferredAddressTypes` to the value captured in `BeforeAll`
  — including restoring it to *unset* when that is what it was — and waits for the agent
  DaemonSet to roll out and reach full readiness. This runs even when the spec failed
  part-way, so a later spec never inherits a modified SNRC.
- `DeferCleanup` tolerates the SNRC having been deleted by another actor, logging with
  `GinkgoWriter.Printf` rather than failing.
- `AfterAll` re-asserts `verifyDSPodsRunning` as a safety net, matching the pattern used by
  the softdog test (OCP-50770), which patches and restores the same SNRC.
- No pods, CRs or node-level state are created, so there is nothing else to remove.

## 12. Implementation sketch

```go
It("Verify preferredAddressTypes is validated, reaches the agent DaemonSet, and causes no remediation",
    reportxml.ID("1928"),
    Label(
        labels.OperatorSNR,
        labels.TierAcceptance,
        labels.ComponentDaemonSet,
        labels.DisruptionNonDestructive,
        labels.PlatformAny,
        labels.TopologyControlPlane,
        labels.FrequencyNightly,
    ), func() {
        DeferCleanup(func() {
            By("DeferCleanup: restoring the original preferredAddressTypes")
            restorePreferredAddressTypes(ctx, originalAddressTypes)
        })

        By("Verifying the agent DaemonSet renders an empty PREFERRED_ADDRESS_TYPES by default")
        // ...

        By("Rejecting a SelfNodeRemediationConfig with an invalid preferredAddressTypes value")
        // ...

        By("Patching the SelfNodeRemediationConfig with preferredAddressTypes InternalIP and NodeName")
        // ...

        By("Consistently verifying no control plane node is remediated or rebooted")
        Consistently(func() error {
            return noControlPlaneRemediation(ctx, cpBootIDs)
        }, snrparams.PreferredAddressNoRemediationDuration,
            snrparams.DefaultPollInterval).Should(Succeed(),
            "No control plane node may be remediated after preferredAddressTypes is set")
    })
```

Reusable from the existing suite: `verifyDSPodsRunning`, `snrcForPatch`,
`listMasterNodes`, `helpers.GetNodeBootIDFromAPI`, `snrparams.DSPodRestartTimeout`,
`snrparams.DefaultPollInterval`, and `snrparams.DaemonSetPodLabelSelector`. The softdog test
in `config_lifecycle.go` (OCP-50770) is the closest existing pattern: it patches the default
SNRC, waits for the DaemonSet to restart, asserts on agent logs, and restores the original
value.

New constants for `tests/snr-operator/internal/snrparams/const.go`:

| Constant                                 | Value | Why                                                                                      |
| ---------------------------------------- | ----- | ------------------------------------------------------------------------------------------ |
| `PreferredAddressTypesEnvVar`            | `"PREFERRED_ADDRESS_TYPES"` | The agent container env var rendered from the SNRC field.                 |
| `PreferredAddressTypesValid`             | `[]string{"NodeName", "Hostname", "InternalDNS", "ExternalDNS", "InternalIP", "ExternalIP"}` | The CRD enum, for step 3. |
| `PreferredAddressTypesInvalid`           | `"NotAnAddressType"` | The rejected value for step 2.                                                   |
| `KubeletReadOnlyPort`                    | `10250` | The port the self-diagnostics check probes.                                           |
| `KubeletDownMessage`                     | `"kubelet service is down"` | The agent log line asserted absent in step 9.                             |
| `PreferredAddressNoRemediationDuration`  | `5m` | The observation window for step 10. Longer than several `apiCheckInterval` ticks (15s default) and than `maxTimeForNoPeersResponse` (30s), so a node that was going to falsely remediate would have done so. |
