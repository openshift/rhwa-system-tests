Covers the product bug [RHWA-1596](https://redhat.atlassian.net/browse/RHWA-1596)
("SNR self-diagnostics fail when node name is not DNS-resolvable, causing false
self-remediation", Bug, ON_QA), fixed by
[self-node-remediation#331](https://github.com/medik8s/self-node-remediation/pull/331),
which closes upstream issues
[#330](https://github.com/medik8s/self-node-remediation/issues/330) and
[#267](https://github.com/medik8s/self-node-remediation/issues/267).

The fix is carried by `medik8s-5.8` — PR #331 merged as `7ef8912` and is an ancestor of the
branch head, and `preferredAddressTypes` is present in `bundle/manifests/`, so it ships
through OLM.

## 2. Summary

SNR's control plane self-diagnostics check the local kubelet at
`https://<address>:10250/pods`. Before the fix that address was always the node's
`metadata.name`, so on clusters where node names are not DNS-resolvable the check always
failed and the node falsely self-remediated. PR #331 adds
`SelfNodeRemediationConfig.spec.preferredAddressTypes`, which selects addresses from
`node.status.addresses` instead. This test proves the new field is validated, reaches the
agent DaemonSet, and leaves a healthy cluster un-remediated.

One property of the agent shapes several steps below: the agent DaemonSet is **not**
host-networked. `install/self-node-remediation-deamonset.yaml` sets `hostPID: true` and
`dnsPolicy: ClusterFirst` but no `hostNetwork`, so the agent resolves the node name through
CoreDNS and dials the kubelet from the pod network. That is exactly why RHWA-1596 bites,
and it means any probe that claims to stand in for the agent must run from a pod on the
cluster network — not from the test runner, and not from an `oc debug` pod (those are
host-networked).

## 3. Scope

- **In scope**:
  - CRD enum validation of `spec.preferredAddressTypes`: the installed CRD's schema offers
    exactly the six documented values (`NodeName`, `Hostname`, `InternalDNS`, `ExternalDNS`,
    `InternalIP`, `ExternalIP`), and anything else is rejected by the API server.
  - The default: with the field unset the agent DaemonSet renders
    `PREFERRED_ADDRESS_TYPES=""`, which the agent treats as `["NodeName"]` — the
    backward-compatible behaviour PR #331 promises.
  - Rendering: a configured list reaches the agent container as a comma-separated
    `PREFERRED_ADDRESS_TYPES` env var **in the configured order**, since order is the
    fallback precedence.
  - Rollout: changing the field restarts every agent pod and all of them return Ready,
    including those on control plane nodes. This matters because the API doc states
    addresses "are currently only read on startup, so a pod restart is required".
  - No false self-remediation: across an observation window after the change, no
    `SelfNodeRemediation` CR appears for any control plane node, no control plane node
    leaves `Ready`, and no control plane node changes its boot ID.
  - A positive control that the configured address type is actually usable **from where the
    agent sits**: a pod on the cluster network, pinned to the control plane node, reaches
    `https://<InternalIP>:10250/pods`.
  - The agent `NetworkPolicy` permits egress to TCP 10250. SNR 5.8 added
    `install/self-node-remediation-networkpolicy.yaml` (`self-node-remediation-ds-np`,
    upstream #373) *after* #331, applying Ingress and Egress policy to the agent pods. Its
    egress allowance for port 10250 is what makes `preferredAddressTypes` usable at all, the
    controller recreates it on every reconcile, and nothing upstream tests it against a real
    cluster. A later tightening of that policy would silently re-open RHWA-1596.
- **Out of scope**:
  - **The address-selection algorithm itself** — fallback to later types, ignoring
    addresses of other types, trying every address of a type, IPv6 via `net.JoinHostPort`,
    and the unresolvable-node-name case. PR #331 added
    `internal/controlplane/manager_test.go` upstream, which covers all seven of these with
    a stub kubelet. Re-testing them on a live cluster would add cost and no coverage.
  - **Driving a control plane node into `isDiagnosticsPassed()`.** See the note below; this
    is the main reason the test case is shaped the way it is.
  - Reproducing the original bug by making node names unresolvable. OCP node names resolve
    by construction, and breaking cluster DNS to prove a negative is destructive and would
    not isolate SNR's behaviour from everything else that would fail.
  - Worker node behaviour. `preferredAddressTypes` is read only on the control plane
    self-diagnostics path.
  - The `endpointHealthCheckUrl` half of `isDiagnosticsPassed()`, which PR #331 does not
    touch.

### Why the self-diagnostics path is not driven end to end

`isDiagnosticsPassed()` — the only caller of the kubelet check — is reached from
`controlplane.Manager.IsControlPlaneHealthy` for exactly two worker-peer responses:

| Worker peer response | What `IsControlPlaneHealthy` returns |
| -------------------- | ------------------------------------- |
| `HealthyBecauseNoPeersWereFound` | `didDiagnosticsPass && canOtherControlPlanesBeReached` |
| `HealthyBecauseMostPeersCantAccessAPIServer` | `didDiagnosticsPass` |

Neither is a usable system-test fixture. The first ANDs the diagnostics result with control
plane peer reachability, so on a cluster with no worker peers an isolated control plane node
reboots whatever the kubelet check says — the diagnostics outcome is unobservable. The second
requires more than half the worker peers to report API-server errors simultaneously, which
cannot be arranged without breaking the cluster for unrelated reasons. Both paths also only
run after peer loss, which is itself destructive.

So the honest division is: the decision logic is unit-tested upstream, and this test case
covers the cluster-level contract — the field is validated, it reaches the agents in the
right form, the agents survive it, and nothing reboots. The last two are what a customer
hitting RHWA-1596 actually needs to be true before changing the setting.

### What upstream already covers, and why these steps still run

PR #331 also added envtest coverage of the DaemonSet rendering, not just the selection
algorithm: `internal/controller/tests/config/selfnoderemediationconfig_controller_test.go`
asserts `PREFERRED_ADDRESS_TYPES == ""` by default and `== "InternalDNS,InternalIP"` when the
field is set. Steps 1 and 10 below therefore duplicate an upstream assertion at the Go level.
They are kept because they make a different claim: that the *OLM-installed* CRD carries the
field, that the shipped operator image renders it, and that a real agent rollout survives it.
Neither is observable in envtest. Readers should not count them as novel coverage.

## 5. Preconditions

Asserted in `BeforeAll`:

1. The SNR operator deployment is Ready and the default `SelfNodeRemediationConfig`
   (`self-node-remediation-config`) exists.
2. Every SNR agent DaemonSet pod is Running with all containers Ready.
3. The original value of `spec.preferredAddressTypes` is captured for restore. On a default
   install it is unset; the test must not assume that.
4. Every control plane node has at least one `InternalIP` in `status.addresses`; otherwise
   skip with a message naming the node.
5. No `NodeHealthCheck` selects control plane nodes. One could legitimately create a
   `SelfNodeRemediation` CR during the observation window and make step 13 fail for a reason
   unrelated to this fix, so the spec skips rather than reporting a false failure.
6. No `SelfNodeRemediation` CR exists for any control plane node.
7. Every control plane node is `Ready`, and its boot ID is recorded. Both feed the
   no-reboot assertion in step 13; the `Ready` baseline is what makes a later transition
   attributable to this test.

## 6. Test steps

| #  | Step (`By` text)                                                                                   | Expected result                                                                            |
| -- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1  | Verifying the agent DaemonSet renders an empty PREFERRED_ADDRESS_TYPES by default                      | With the field unset, the agent container's `PREFERRED_ADDRESS_TYPES` env var is present and empty, which the agent treats as `["NodeName"]` |
| 2  | Reading the preferredAddressTypes enum from the installed SelfNodeRemediationConfig CRD                | The storage version's `spec.preferredAddressTypes` is an array whose `items.enum` is exactly `snrparams.PreferredAddressTypesValid` — no missing value, no extra value |
| 3  | Rejecting a SelfNodeRemediationConfig with an invalid preferredAddressTypes value                      | A **server-side dry-run** patch with `["NotAnAddressType"]` is rejected by the API server with an enum validation error naming the field, and the live SNRC is unchanged |

| 5  | Verifying the kubelet answers on the InternalIP of each control plane node from the pod network        | A run-to-completion probe pod on the cluster network, pinned to the node and tolerating the control plane taints, gets an HTTP response from `https://<InternalIP>:10250/pods` (401 is success — it proves the port is served to a pod-network client) |
| 6  | Verifying the agent NetworkPolicy permits egress to the kubelet port                                   | `self-node-remediation-ds-np` exists in `medik8sparams.OperatorNs`, selects the agent pods, and has an egress rule allowing TCP `snrparams.KubeletSecurePort` |

| 10 | Verifying PREFERRED_ADDRESS_TYPES is rendered comma-separated in the configured order                  | The agent container env var equals exactly `InternalIP,NodeName` — order preserved, since it is the fallback precedence |
| 11 | Verifying every agent pod on a control plane node is Running and Ready                                 | No agent pod is in CrashLoopBackOff and every control plane node has a Ready agent pod      |
| 12 | Verifying no agent pod logs a kubelet service failure for the configured addresses                     | `kubelet service is down` is absent from every control plane agent pod's log for the window since the rollout |
| 13 | Consistently verifying no control plane node is remediated or rebooted                                 | For `snrparams.PreferredAddressNoRemediationDuration`, no `SelfNodeRemediation` CR exists for any control plane node, every control plane node stays `Ready`, and every control plane boot ID is unchanged |
| 14 | DeferCleanup: restoring the original preferredAddressTypes                                             | The SNRC returns to its captured original spec, including back to *unset*. Skipped as a no-op when the spec failed before step 8 and the value never changed |
| 15 | DeferCleanup: waiting for the agent DaemonSet to roll out after the restore                            | Every agent pod is *replaced* (new UIDs) and Running, so the spec does not exit while the DaemonSet is still converging |

Three of these steps are shaped deliberately and a reviewer should not "simplify" them back:

**Steps 3 and 4 use `client.DryRunAll`, not live patches.** Every accepted write to the
default SNRC changes the agent pod template, which rolls every agent pod in the cluster. Six
live patches in step 4 would mean six full DaemonSet rollouts at up to
`snrparams.DSPodRestartTimeout` each, for no added signal. Dry-run exercises the same API
server validation at no cost; it is already the repo's idiom in
`far_negative_validation.go:207` and `nmo_control_plane_quorum.go:217`. Step 2 then reads the
enum straight off the CRD, the way OCP-60824 reads a field description — one `Get`, and
unlike six individual patches it also catches a value that is *missing* from the enum.

**Step 5 runs from a pod, not from the test runner or `oc debug`.** See §2: the agent is on
the pod network with `dnsPolicy: ClusterFirst`. Probing node IPs from the test binary tests
the runner's network — on most CI topologies it cannot reach `10250` at all and would fail
for a reason unrelated to SNR. An `oc debug node/<x>` pod is host-networked, so it would
bypass precisely the path that breaks in RHWA-1596. The probe is built with
`pod.NewBuilder(...).DefineOnNode(node).WithTolerationToMaster().WithTolerationToControlPlane()`
and `WithRestartPolicy(corev1.RestartPolicyNever)`, reading the result from pod logs rather
than `ExecCommand` — the same run-to-completion pattern, and for the same reason, as the SBR
watchdog probe (`tests/sbr-operator/tests/watchdog.go:100-116`): `ExecCommand` resolves the
external API hostname over SPDY and fails in disconnected clusters, while pod logs go through
`kubernetes.default.svc`. This matters here because §4 claims disconnected support.

**Step 9 asserts pod replacement by UID, not `observedGeneration`.** `observedGeneration`
advances on any reconcile, including a no-op one, so it would pass even if the pods never
restarted — and the restart is load-bearing, since addresses are read only at agent startup.
`collectDSPodUIDs` / `verifyDSPodsReplaced` already exist and are what the softdog test
(OCP-50770) uses at `config_lifecycle.go:103-115`.

**Step 13 trips on `Ready`, not on the boot ID, and the distinction is the whole assertion.**
A watchdog reset does not change `status.nodeInfo.bootID` when it happens — the ID only
changes once the node has rebooted, come back and re-registered, which was measured at
**3m39s–5m** across two clusters (reset 19:34:07 / `Ready` 19:39:14; and `Ready` lost 21:55:25 / new boot ID 21:59:04). That is
longer than the observation window, so a boot-ID-only check cannot see the very reboot it
exists to catch; it would report a pass while two control plane nodes were rebooting.
`Ready` flips to `False`/`Unknown` within `node-monitor-grace-period` (~40s), which does fit.
The boot-ID comparison is kept as confirmation for the case where a reboot completes fast
enough to land inside the window, not as the detector.

This also bounds the window. SNR takes `maxApiErrorThreshold` (3) x `apiCheckInterval` (15s)
= 45s to decide the API is unreachable, then `maxTimeForNoPeersResponse` (30s) waiting for
peers, which predicts ~90s. Measured fire times plus the ~40s detection cost fit inside 4 minutes. That figure is measured, not derived: the two reboots actually observed fired at
**79s and 169s** after the rollout completed, so the arithmetic understates reality by up to
2x. A 3-minute window cleared the 169s event by 11 seconds — luck rather than margin.

Transient API read errors in step 13 are logged and tolerated rather than failed, since a
dropped request is not a remediation. An `observedOK` flag guards the other direction: if
*every* read in the window failed, the spec reports the run inconclusive instead of passing.

Step 12 is a weak assertion by design and is documented as such: on a healthy cluster the
self-diagnostics path never runs, so the message would be absent either way. It is kept
because it costs nothing and would catch an agent that somehow runs the kubelet check at
startup and fails it. Step 13 is the assertion that carries the regression value — it is what
would have failed on an affected cluster before PR #331.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1928")` runs and passes.
- With `preferredAddressTypes` unset, the agent container's `PREFERRED_ADDRESS_TYPES` env var
  is present and empty.
- The installed CRD's `items.enum` for the field is exactly the six documented values.
- An invalid address type is rejected by a dry-run patch; all six documented values are
  accepted by one.
- Each control plane node's kubelet answers on `https://<InternalIP>:10250/pods` from a pod
  on the cluster network, and `self-node-remediation-ds-np` allows agent egress to TCP 10250.
- After patching to `["InternalIP", "NodeName"]`, every agent pod UID changes, the env var is
  exactly `InternalIP,NodeName`, and the DaemonSet reaches full readiness within
  `snrparams.DSPodRestartTimeout`.
- Every control plane node has a Running, Ready agent pod with no restarts attributable to
  the configuration change.
- For `snrparams.PreferredAddressNoRemediationDuration` after the rollout, no
  `SelfNodeRemediation` CR exists for any control plane node, no control plane node leaves
  `Ready`, and no control plane node's `status.nodeInfo.bootID` changes.
- Cleanup finishes: the SNRC's `preferredAddressTypes` is back to the value captured in
  `BeforeAll`, the DaemonSet has rolled out again, and all agent pods are Ready.

On a build without PR #331 this spec fails at step 2: `preferredAddressTypes` is absent from
the CRD schema, so the enum read finds nothing (and steps 3, 4 and 8 would then be rejected
as an unknown field). That is the simplest regression signal; the no-remediation assertion in
step 13 is what protects the behaviour once the field exists.

## 9. Cleanup

- `DeferCleanup` restores `spec.preferredAddressTypes` to the value captured in `BeforeAll`
  — including restoring it to *unset* when that is what it was. This runs even when the spec
  failed part-way, so a later spec never inherits a modified SNRC.
- The restore then waits for the agent pods to be **replaced** (`verifyDSPodsReplaced` against
  UIDs captured immediately before the restore patch), not merely to be Running. Waiting on
  `verifyDSPodsRunning` alone is a no-op here: the restore changes the pod template, so the
  rollout is pending but has not started, and the pre-restore pods are still Running at that
  instant. An earlier version did exactly that and returned in under a second, letting the
  spec report done while the DaemonSet was still converging.
- When the spec fails before step 8, the SNRC still holds its original value and the restore
  is a no-op. It is skipped in that case: patching would be harmless, but then waiting for a
  rollout that never happens would block for `snrparams.DSPodRestartTimeout`.
- `DeferCleanup` tolerates the SNRC having been deleted by another actor, logging with
  `GinkgoWriter.Printf` rather than failing.
- `AfterAll` re-asserts `verifyDSPodsRunning` as a safety net, matching the pattern used by
  the softdog test (OCP-50770), which patches and restores the same SNRC. It first checks the
  SNRC still exists and fails fast with an explicit message if not: the DaemonSet is owned by
  the SNRC, so with no SNRC there will never be agent pods and the poll would otherwise burn
  the full `DSPodRestartTimeout` to reach the same conclusion. The default SNRC is an operator
  operand, recreated only at operator startup — deleting it by hand disables SNR cluster-wide
  and breaks every later SNR spec.
- Each step 5 probe pod is removed by its own `DeferCleanup`, best-effort and logging rather
  than failing on a delete error — the same shape as the SBR watchdog probe cleanup. The pods
  use `RestartPolicyNever` and exit on their own, so a leaked pod is `Succeeded`, not running.
- Steps 3 and 4 write nothing: `client.DryRunAll` means there is no SNRC state to undo from
  the validation steps, only from step 8.
- No other CRs or node-level state are created.

## 12. Implementation sketch

```go
It("Verify preferredAddressTypes is validated, reaches the agent DaemonSet, and causes no remediation",
    reportxml.ID("1928"),
    Label(
        labels.OperatorSNR,
        labels.TierAcceptance,
        labels.ComponentDaemonSet,
        labels.DisruptionDestructive,
        labels.PlatformAny,
        labels.TopologyControlPlane,
        labels.FrequencyNightly,
    ), func() {
        DeferCleanup(func() {
            By("DeferCleanup: restoring the original preferredAddressTypes")
            restorePreferredAddressTypes(ctx, originalAddressTypes)
        })

        By("Verifying the agent DaemonSet renders an empty PREFERRED_ADDRESS_TYPES by default")
        // ...

        By("Reading the preferredAddressTypes enum from the installed SelfNodeRemediationConfig CRD")
        // Get snrparams.SNRCRDName, walk to the storage version, and compare
        // spec.properties.preferredAddressTypes.items.enum to PreferredAddressTypesValid.

        By("Rejecting a SelfNodeRemediationConfig with an invalid preferredAddressTypes value")
        invalidPatch := []byte(fmt.Sprintf(
            `{"spec":{"preferredAddressTypes":[%q]}}`, snrparams.PreferredAddressTypesInvalid))
        err := APIClient.Patch(ctx,
            snrcForPatch(snrparams.SNRConfigName),
            client.RawPatch(types.MergePatchType, invalidPatch),
            client.DryRunAll)
        Expect(err).To(HaveOccurred(),
            "API server must reject an invalid preferredAddressTypes value")
        Expect(err.Error()).To(ContainSubstring("preferredAddressTypes"))

        By("Verifying the kubelet answers on the InternalIP of each control plane node from the pod network")
        // Run-to-completion probe pod per control plane node; read the result from its logs.
        probePod, createErr := pod.NewBuilder(
            APIClient, probeName, medik8sparams.OperatorNs, snrparams.WorkloadTestImage).
            DefineOnNode(nodeName).
            WithTolerationToMaster().
            WithTolerationToControlPlane().
            WithRestartPolicy(corev1.RestartPolicyNever).
            RedefineDefaultCMD([]string{
                "sh", "-c",
                fmt.Sprintf("curl -sS -k -o /dev/null -w '%%{http_code}' https://%s/pods",
                    net.JoinHostPort(internalIP, snrparams.KubeletSecurePort)),
            }).
            Create()

        By("Capturing the current agent pod UIDs")
        prePatchUIDs := collectDSPodUIDs()

        By("Patching the SelfNodeRemediationConfig with preferredAddressTypes InternalIP and NodeName")
        // ... live MergePatch, no DryRunAll this time

        By("Waiting for every agent pod to be replaced after the configuration change")
        Eventually(func() error {
            return verifyDSPodsReplaced(prePatchUIDs)
        }, snrparams.DSPodRestartTimeout, snrparams.DefaultPollInterval).Should(Succeed(),
            "SNR DaemonSet pods must be replaced after preferredAddressTypes changes")

        By("Consistently verifying no control plane node is remediated or rebooted")
        Consistently(func() error {
            return noControlPlaneRemediation(ctx, cpBootIDs)
        }, snrparams.PreferredAddressNoRemediationDuration,
            snrparams.DefaultPollInterval).Should(Succeed(),
            "No control plane node may be remediated after preferredAddressTypes is set")
    })
```

Reusable from the existing suite, all verified to exist: `verifyDSPodsRunning`,
`verifyDSPodsReplaced`, `collectDSPodUIDs`, `snrcForPatch`, `listMasterNodes`,
`helpers.GetNodeBootIDFromAPI`, `helpers.GetNodeInternalIP`, `snrparams.SNRConfigName`,
`snrparams.SNRCRDName`, `snrparams.WorkloadTestImage`, `snrparams.DSPodRestartTimeout`,
`snrparams.DefaultPollInterval`, and `snrparams.DaemonSetPodLabelSelector`. The softdog test
in `config_lifecycle.go` (OCP-50770) is the closest existing pattern: it patches the default
SNRC, waits for the DaemonSet pods to be replaced by UID, asserts on agent logs, and restores
the original value. For the step 5 probe pod, `tests/sbr-operator/tests/watchdog.go:100-135`
is the pattern to copy.

`createWorkloadPodOnNode` is **not** reusable for step 5: it sets no tolerations, so it
cannot schedule onto a tainted control plane node. The probe needs its own builder chain
with `WithTolerationToMaster()` and `WithTolerationToControlPlane()`.
