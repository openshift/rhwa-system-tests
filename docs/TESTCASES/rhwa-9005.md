## 2. Summary

The WAO manager answers the five SNR admission entries. This test sends `SelfNodeRemediationConfig`, `SelfNodeRemediationTemplate` and `SelfNodeRemediation` requests with server-side dry-run while the SNR operand is `Disabled`, and again while it is `Enabled`. While SNR is `Enabled` it also sends dry-run update and delete requests for the default objects that the SNR manager creates.

## 3. Scope

- **In scope**: SNR rules SNR-1 to SNR-10 of `docs/wao-webhooks-test-plan.md`: the singleton name and namespace (the namespace comes from the `OPERATOR_NAMESPACE` variable of the WAO Deployment), the duration minimums, the toleration and node selector rules, the two warnings, the template defaulter, and the `OutOfServiceTaint` strategy, which depends on the Kubernetes version that WAO reads at start.
- **Out of scope**:
  - **The operand controllers.** Remediation, fencing and maintenance belong to the operator
    suites. This spec stores no remediation request and starts no maintenance.
  - **SBR admission.** The SBR operand serves its own webhooks.
  - **CRD schema validation.** A request that the API server rejects before admission does not
    reach a webhook. The operator suites cover those cases.
  - **The `Ignore` policy of `vselfnoderemediation.kb.io`.** RHWA-9006 covers it.
  - **The rejection of `OutOfServiceTaint`.** It occurs only on Kubernetes earlier than 1.26.
  - **The strategy enum.** The CRD schema rejects a value that is not in the enum. Specs 60877 and 60822 of
    `tests/snr-operator` cover it.

## 5. Preconditions

The spec has no `BeforeAll`. Its first step records which default SNR objects exist
(`self-node-remediation-config` and `self-node-remediation-automatic-strategy-template`), so that it can
remove at the end only the objects that the SNR manager created during the run.

The spec accepts each start state of the SNR operand. It records the state and restores it.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("9005")` runs and passes.
- Each request gets the answer in the table.
- The spec stores no SNR object. The dry-run delete and the dry-run updates change nothing.
- Cleanup finishes: `spec.components.selfNodeRemediation.enabled` has the value of the start. If SNR was
  `Disabled` and had no config at the start, the phase is `Disabled` again and no agent DaemonSet remains.

## 9. Cleanup

- The last steps of the `It` remove the default config and the default template, if the SNR manager created
  them during the run and SNR is disabled again. The config owns the agent DaemonSet, so garbage collection
  removes the agents.
- `DeferCleanup` sets the SNR operand to the intent of the start. It writes a failure to the log.
- `AfterAll`: none.
- Manual recovery after a failed run that leaves SNR `DisableIncomplete`:
  `oc delete selfnoderemediationconfig --all -n openshift-workload-availability`.

## 11. Running it standalone

```bash
ginkgo -v --label-filter="component:webhook && operator:wao" \
    --focus="RHWA-9005" ./tests/wao-operator/...
```

The webhook run script selects the spec together with the other webhook specs:

```bash
make run-webhook-tests WEBHOOK_TARGET=snr
```

Watch the cluster while it runs:

```bash
watch -n 5 -d tools/watch/webhook-watch.sh   # Linux, or macOS with `brew install watch`
tools/watch/webhook-watch.sh --loop          # anywhere, no `watch` needed
```

What must change: the `selfNodeRemediation` row goes `Disabled` → `Available`, and the
`self-node-remediation-ds` pods start on each node. When SNR was `Disabled` at the start, the row goes to
`DisableIncomplete` and then to `Disabled`, and the agent pods go. What must not change: `ADMIT` stays
`true`, and no `selfnoderemediation` object appears in the stored objects block.
