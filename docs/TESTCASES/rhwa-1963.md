# RHWA-1963 — Process churn on a node never costs its SBR agent its liveness probe, its container, or its watchdog

## 2. Summary

The sbr-agent's container probes locate the agent by scanning every process on the
host. A process that exits mid-scan makes the scan exit non-zero even though it
found the agent, so a busy node manufactures probe failures; three consecutive
liveness failures make kubelet restart the agent, which releases `/dev/watchdog`.
This test puts process churn on one node and proves the agent is neither reported
unhealthy nor restarted — first on a healthy node, then on a node that has also
lost its Ceph storage, where a restarted agent cannot come back and nothing would
be left on the node to reboot it.

## 3. Scope

- **In scope**
  - The sbr-agent liveness probe's exit status on a node under heavy process
    churn, sampled directly from the container rather than inferred from kubelet
    events.
  - The agent container's restart count under that churn.
  - kubelet never deciding to restart the agent container over its liveness probe.
  - The same, on a node whose Ceph RBD traffic is rejected at the host firewall,
    plus proof that a process on that node still holds a watchdog device open.
  - Block mode on Ceph RBD only — the `StorageBasedRemediationConfig` is created
    with `sharedStorageVolumeMode: Block` against an RWX Block RBD StorageClass.

- **Out of scope**
  - The readiness probe. It scans the process table the same way and fails under
    the same churn, but this test only asserts that the agent pod is Ready at the
    points where it must be; it does not sample or count readiness failures.
  - The startup probe.
  - Whether a storage-isolated node is correctly fenced and rebooted — that is
    RHWA-1944 (`block_storage_total_loss.go`), which runs with a NodeHealthCheck
    and expects the reboot. This test deliberately runs with *no* NHC on the SBR
    template so that nothing creates a `StorageBasedRemediation` CR and the only
    thing that could remove the agent is its liveness probe.
  - Detection-only mode — RHWA-1961 (`block_storage_detect_only.go`).
  - Filesystem mode. The probes are mode-independent, but this spec only
    exercises Block mode.
  - Recovering a node whose kernel RBD client was left unusable by the injected
    Ceph outage. See section 8.

## 5. Preconditions

1. `SBR_RUN_LIVENESS_CHURN` is set. Unset, both specs `Skip` because RHWA-1955
   is still open — see section 8.
2. No `NodeHealthCheck` remediates through the SBR template (`requireNoSBRNodeHealthCheck`).
   With one, a remediation CR would be created for the storage-isolated victim in
   the second spec and the node would correctly reboot — which would remove the
   agent for a reason that has nothing to do with the probe. The spec `Skip`s.
3. Self Node Remediation is not running (`failIfSNRRunning`) — both operators
   claim `/dev/watchdog`.
4. A Ceph RBD StorageClass exists, or `SBR_RBD_STORAGE_CLASS` names one.
   Otherwise the spec `Skip`s.
5. Any `StorageBasedRemediationConfig` named `test-sbrc-block-liveness-churn` left
   by an earlier run is deleted and waited out before the new one is created.
6. The Block device-init Job for the new config succeeds, and every agent in its
   DaemonSet is Ready.
7. A schedulable worker node that hosts no SBR controller pod exists; its agent
   pod is Running and Ready. Otherwise the spec `Skip`s.
8. A second node runs a Ready agent of the same config — it is the control for the
   watchdog-holder scan in steps 24–25.

## 7. Pass criteria

- Two specs with `reportxml.ID("1963")` run and pass.
- In both windows, zero of the liveness-probe samples taken from the victim's
  agent container exited non-zero. The command sampled is read off the live
  DaemonSet, so it is exactly what kubelet runs; when the container defines no
  liveness probe at all the sampling is skipped and logged, which is the fixed
  state.
- In both windows, the victim agent's total container restart count never moves
  from its baseline for the whole of `sbrparams.BlockChurnObserveDuration`.
- No `Container sbr-agent failed liveness probe, will be restarted` event is
  recorded against the victim's agent pod after the window's cutoff.
- The churn pod stays Running for the whole of both windows — a window in which
  it died proves nothing and fails.
- In the second spec the victim node stays `Ready=True` throughout, its agent pod
  is Ready at the end, and the watchdog-holder scan finds at least one holder on
  the victim — with the same scan having found one on the control node first.
- Cleanup finishes: both churn pods, the injector pod and the
  `StorageBasedRemediationConfig` with its DaemonSet and PVC are gone, and no
  Ceph REJECT rule is left on the victim's `OUTPUT` or `INPUT` chain.

## 9. Cleanup

- `DeferCleanup` removes what each `It` created: the first spec's churn pod; the
  second spec's churn pod, its injector pod, and any Ceph REJECT rule left on the
  victim.
- `AfterAll` removes what `BeforeAll` created: the
  `StorageBasedRemediationConfig`, and with it the agent DaemonSet and the shared
  storage PVC. It also deletes both churn pods and the injector pod, and flushes
  the victim's Ceph REJECT rules, tolerating anything already gone.
- Recovery runs even when a spec failed mid-way: the churn pods and the injector
  are deleted and the rules flushed from `AfterAll` before the config is removed,
  and each spec's `DeferCleanup` repeats its own share. Every cleanup step
  tolerates `IsNotFound` and logs with `GinkgoWriter.Printf` rather than failing
  the suite.
- Step 31 waits for the victim's agent to come back and records a report entry if
  it does not, rather than asserting — a node left without an agent must be
  visible here instead of being inherited silently by the next spec.
- Not covered by cleanup: a kernel RBD client left unusable by the injected
  outage. See section 8.

## 11. Running it standalone

Both specs — the second depends on the first's `BeforeAll`, and the Describe is
`Ordered`, so focusing on the Describe is the normal way to run it:

```bash
export SBR_RUN_LIVENESS_CHURN=1
ginkgo -v --label-filter="operator:sbr && component:daemonset" \
    --focus="SBR Block Storage — Ceph RBD Liveness Probe Under Process Churn" \
    ./tests/sbr-operator/...
```

Expect roughly 30 minutes: two 10-minute observation windows plus config setup,
the Block device-init Job and teardown.
