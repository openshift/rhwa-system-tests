# RHWA-1965 — The sbr-agent probes must not restart a healthy agent, and a node reported fenced must have rebooted

This is the regression test for the product bug
[RHWA-1955](https://issues.redhat.com/browse/RHWA-1955) — *"SBR-agent liveness
probe fails on a healthy agent and restarts it"*. RHWA-1955 is a `Bug`, so it
cannot be the test case ticket; RHWA-1965 is the `TEST:` Task that tracks this
document and its spec.

## 2. Summary

The sbr-agent DaemonSet decides the agent is alive by grepping every process on
the node, and the pod runs with `hostPID`, so a process exiting mid-scan makes
the scan fail on a perfectly healthy agent. This test puts continuous process
churn on one node and proves no agent is restarted by it, then keeps the churn
running while that node is cut off from Ceph and proves the end state SBR must
never reach: a node reported fenced, tainted `out-of-service` and moved off, that
in fact never rebooted.

## 3. Scope

- **In scope**: that the agent DaemonSet defines no liveness and no startup
  probe and no remaining probe that decides liveness by scanning `/proc`; that
  continuous host process churn restarts no agent pod and produces no kubelet
  probe-failure event; that a process still holds the watchdog device open on
  the churned node; and that once SBR reports `FencingSucceeded=True` and
  `Succeeded=True` for a storage-isolated node under churn, that node's boot-id
  actually changes.
- **Out of scope**:
  - Split-brain geometry — that only the isolated node is fenced and the
    witnesses are untouched (`block_storage_split_brain.go`, RHWA-1934).
  - Heartbeat stability under pure CPU saturation, with no process churn and no
    restart or event assertions (`block_storage_heartbeat_load.go`, RHWA-1925).
  - Recovery from a *transient* Ceph RBD partition with no fencing at all
    (`block_storage_transient_partition.go`, RHWA-1924).
  - The watchdog self-fencing path on RWX Filesystem storage
    (`storage_loss_watchdog.go`, OCP-88880).
  - Agent startup when `/dev/watchdog` is already held by another process
    (`detect_only.go`, RHWA-1068).
  - Whether the probes were removed or rewritten upstream. The spec asserts the
    shape the fix landed on (no liveness, no startup, no `/proc` scan) rather
    than reproducing the `grep` exit-code race directly, which cannot be forced
    deterministically from a test.

## 5. Preconditions

1. `SBR_TEST_RHWA1955=true`; otherwise the test skips before creating anything.
2. The `NodeHealthCheck` CRD is installed (otherwise the test skips).
3. No `NodeHealthCheck` from a prior run of this test (`nhc-sbr-agent-probe`) —
   it is deleted and waited out in `BeforeAll`.
4. No other `NodeHealthCheck` remediates through the SBR template
   (`requireNoSBRNodeHealthCheck`), which would fence a node independently.
5. Self Node Remediation is not running (SNR and SBR cannot share the watchdog).
6. A Ceph RBD `volumeMode: Block` StorageClass exists; a stale
   `test-sbrc-agent-probe` SBRC is deleted and waited out before the new one is
   created.
7. The SBRC's agent DaemonSet becomes ready and the SBRC reports
   `status.storageValidation.concurrentWriteable=true`.
8. At least one schedulable worker node hosts no SBR controller pod; that one is
   the target, so the fencing reboot does not take the operator down mid-test.
   Otherwise the test skips.

## 6. Test steps

| #  | Step (`By` text)                                                                                        | Expected result                                                                                   |
| -- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1  | Asserting the agent container defines no liveness or startup probe                                      | The `sbr-agent` container has `livenessProbe` and `startupProbe` unset, and any readiness probe left does not scan `/proc`; the probe configuration is logged |
| 2  | Recording every agent pod's container restart count before the churn                                    | Each agent's node, pod name and restart count recorded; the target node has a Running agent pod   |
| 3  | Starting a host-PID pod that spawns short-lived processes on node `<target>`                            | A privileged `hostPID` pod is Running on the target node, spawning and reaping bursts of 50 processes for 20 minutes |
| 4  | Consistently asserting for 6m that no agent pod is restarted while the target node's process list churns | For 6 minutes every agent is the same pod with the same container restart count                   |
| 5  | Asserting no agent pod recorded a failed-probe event during the churn                                   | No Event whose message mentions a probe exists against any agent pod                              |
| 6  | Asserting a process on node `<target>` still holds the watchdog device open                             | The host-PID watchdog check exits `Succeeded` and reports `held by /proc/<pid>`                   |
| 7  | Creating the NodeHealthCheck CR that remediates SBRStorageUnhealthy nodes through SBR                   | `NodeHealthCheck/nhc-sbr-agent-probe` with `maxUnhealthy: 1` exists                               |
| 8  | Recording the target node's boot-id before its Ceph traffic is blocked                                  | Pre-fencing boot-id read and logged                                                               |
| 9  | Blocking Ceph ports on node `<target>` while the process churn continues                                | OUTPUT REJECT rules for ports 3300, 6789 and 6800–7300 applied on the target node only            |
| 10 | Waiting for SBRStorageUnhealthy=True (reason HeartbeatTimeout) on the target node                       | A peer sets `SBRStorageUnhealthy=True` with reason `HeartbeatTimeout`, and the target's agent has not been restarted |
| 11 | Waiting for NHC to create a StorageBasedRemediation CR for the target node                              | `StorageBasedRemediation/<target>` exists, and the target's agent has not been restarted          |
| 12 | Waiting for FencingSucceeded=True and Succeeded=True on the target's StorageBasedRemediation CR         | Both conditions reach True, and the target's agent has not been restarted                         |
| 13 | Asserting the node reported fenced actually rebooted (its boot-id changed)                              | The target's boot-id differs from the one recorded in step 8                                      |
| 14 | Waiting for node `<target>` to come back Ready with a Ready agent pod                                   | The target reports `Ready=True` and this SBRC's agent pod on it reaches `PodReady=True`           |
| 15 | Waiting for NHC to delete the StorageBasedRemediation CR and the out-of-service taint to be removed     | `StorageBasedRemediation/<target>` is gone, the node carries no `out-of-service` taint and is schedulable |

Steps 10 to 12 each fail fast with `StopTrying` on the signature RHWA-1955
produces: the target's agent gains a container restart while the node is still
`Ready` on the boot-id recorded in step 8. That restart releases the watchdog,
the replacement cannot complete preflight without the storage, and the scenario
can no longer end correctly. A node that has rebooted, gone `NotReady` or
dropped out of the API restarts its agent as a matter of course, so none of
those trips the guard.

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1965")` runs and passes.
- The `sbr-agent` container in DaemonSet `sbr-agent-test-sbrc-agent-probe` has
  no `livenessProbe` and no `startupProbe`, and no remaining probe whose exec
  command contains `/proc/`.
- For `AgentProbeNoRestartDuration` (6 minutes) of continuous process churn on
  the target node, every agent pod of the SBRC keeps its name and its container
  restart count, and no Event mentioning a probe is recorded against any of them.
- A host process holds a watchdog device open on the target node after the churn.
- With the churn still running and Ceph blocked, a peer reports the target
  `SBRStorageUnhealthy=True` (reason `HeartbeatTimeout`) within
  `StorageInjectionTimeout`, NHC creates one `StorageBasedRemediation` named
  after it within `NHCSBRCRCreationTimeout`, and that CR reaches
  `FencingSucceeded=True` and `Succeeded=True` within `FencingProvenTimeout` —
  with the target's agent never gaining a restart while the node is still Ready
  on its pre-fencing boot-id.
- The target's boot-id changes within `NodeRebootTimeout` of fencing being
  proven. A run where fencing is proven and the boot-id never changes fails:
  the cluster has declared a running node dead.
- The target returns `Ready`, its agent pod reaches `PodReady=True`, NHC deletes
  the CR, and the node ends schedulable with no `out-of-service` taint.
- Cleanup finishes: the NHC, SBRC, churn pod, watchdog pod and injector pod are
  gone, no `StorageBasedRemediation` remains, the target is uncordoned, and any
  leftover Ceph REJECT rule is flushed.

## 8. Failure / known issues

| Bug | Effect | Gate |
| --- | ------ | ---- |
| [RHWA-1955](https://issues.redhat.com/browse/RHWA-1955) — sbr-agent liveness probe fails on a healthy agent and restarts it | On a build without the fix, step 1 fails on the liveness/startup probes still being defined. On a build where the probes exist and the node is busy, steps 4 and 5 fail: kubelet records `Liveness probe failed` and restarts a healthy agent. If such a restart lands while the node is cut off from Ceph, steps 10–12 stop early and step 13 is the end state the bug produces — a node reported fenced that never rebooted. | `SBR_TEST_RHWA1955=true` |

RHWA-1955 is a 5.8 blocker, fix version `rhwa-5.8-0`, in `POST` as of
2026-10-27. Remove the gate and set this document's status to `implemented` once
the fix is in every build the suite runs against.

Validated against the fix on 2026-10-27: SBR 5.8.0 (`quay.io/rhn_engineering_whayutin/
storage-based-remediation-agent:dev`) plus NHC 5.8.0 on a 3-master/3-worker OCP
cluster with external Ceph RBD. One spec passed in 994s. The fixed DaemonSet
carries no liveness and no startup probe; the surviving readiness probe is
`test -f /var/run/sbr-agent/preflight-ok && test -c /host-dev/watchdog`, which
touches no process table. Timings, for anyone sizing the waits: SBRC ready 96s,
`SBRStorageUnhealthy=True` 41s after the Ceph block, NHC created the CR 31s
later, `FencingSucceeded`/`Succeeded` 5.4s after that, boot-id changed ~4.5min
later, node and agent Ready ~2.5min after the reboot.

Two behaviours a watcher will see mid-run that are normal and must not be read as
failures. First, `SBRStorageUnhealthy` oscillates `True` -> `Unknown`
(`GivingAgentChance`) on roughly a 30s cycle at `sbrTimeoutSeconds: 10`, and NHC
deletes and recreates the remediation CR along with it, so `oc get
storagebasedremediations` is empty for much of the run — fencing is proven inside
the first `True` window, long before that cycling matters. Second, the target's
agent restart count goes from 0 to 1 when the node reboots, because kubelet
restarts the container on the way back up; that is why the fail-fast guard keys on
"restart while the node is still Ready on its pre-fencing boot-id" rather than on
the restart count alone. Read `/tmp/<log>` for the spec's own `By` steps rather
than inferring progress from `oc` polling: the cluster view lags and invites
exactly these two misreadings.

Two notes, neither a known bug. The spec asserts the probe *shape* the fix landed
on rather than reproducing the `grep` exit-code race: the race depends on a
process exiting inside the scan, which cannot be forced deterministically, so the
behavioural half of the test is "no restart and no probe event under heavy churn"
and the structural half pins the configuration that made the race reachable. And
the churn is deliberately heavy — bursts of 50 processes spawned and reaped in a
tight loop, comparable to the saturation `block_storage_heartbeat_load.go`
already applies — because a weak stressor would let the test pass vacuously.

## 9. Cleanup

- `DeferCleanup` removes the process churn pod, the `NodeHealthCheck` CR, and
  the injector pod, and flushes any Ceph REJECT rule left on the target node.
- `AfterAll` removes the `NodeHealthCheck`, the churn, watchdog and injector
  pods, flushes leftover Ceph rules on the target, force-removes any
  `StorageBasedRemediation` for the target, uncordons it if still cordoned, and
  deletes the SBRC (waiting for it to be gone). All tolerate `IsNotFound` and
  log rather than fail. Everything except the SBRC delete is guarded on
  `BeforeAll` having run to completion: a run that skipped on the env gate or a
  missing CRD created nothing, and `cleanupNHCCR` would otherwise poll its full
  `NHCCleanupTimeout` against a cluster that has no NodeHealthCheck CRD.
- Recovery (iptables flush, uncordon, churn pod removal) runs even when the spec
  failed mid-way. The churn script bounds itself to
  `AgentProbeChurnDuration` (20 minutes) so the load ends on its own if the test
  dies before `DeferCleanup` runs.
- `BeforeAll` pre-cleans this test's own stale NHC and SBRC from a prior run and
  waits for them to be fully gone before recreating.
